# Последствия одной поправки до конца боя

23.10.2026. Дополнительная диагностическая проверка, без обучения и новых игр. Фиксируется до сравнительного чтения конечных исходов 130 поздних one-frame повторов. До протокола читались completion/error counts, схема rewards и один суммарный reward baseline; исходы альтернатив между собой не сравнивались. Основной fixed500 протокол и его пороги не меняются.

Задача: проверить, совпадает ли предпочтение по урону одного выстрела с предпочтением по оставшейся награде боя. Метка immediate HP может не отражать полезность манёвра в целом. Использовать только новый one-frame набор: после заданного кадра остаётся исходный kernel, однако состояния и дальнейшие решения могут расходиться. Старые constant-head captures сюда не включать: у них вмешательство может повториться позже.

Допуск пары — принятый существующим native prefix auditor baseline и альтернативный вариант. Сохранить заранее назначенные train/development группы. Не считать разные состояния одного seed независимыми боями. Исключения и несовпадения показать явно; не перезапускать ради желаемого результата.

Связать intervention frame с index строки steps и reward.step. Проверить уникальность индексов, наличие доступной награды вмешательства, равенство всех reward rows до вмешательства между вариантами. Суммировать от вмешательства включительно до конца first-life capture. Показать две заранее заданные величины: сумму существующего полного reward score и сумму его компонентов monster_damage, received_damage, self_damage_extra, friendly_damage, death, monster_kill, tick. Коэффициенты взять из запечатанного reward-config каждого повтора (v13: damage 0.01, received -0.02, death -5, kill +5); никакого подбора коэффициентов по исходам. Discount в этом описательном отчёте не применять. Временное усечение не объявлять победой или полным бесконечным return.

Для каждого контекста сохранить baseline, immediate HP, обе суммы награды и delta по каждому принятому действию. С допуском численного сравнения 1e-6 показать число контекстов с положительной альтернативой, с разным лучшим действием immediate/full/sparse, а также случаи immediate improvement с худшим последующим full/sparse return. Представлять отдельно train/development и число уникальных seed. Сравнение чисел внутри одного seed/состояния — условный одиночный rollout, не оценка ожидаемого Q и не доказательство причинной оптимальности действия при другой случайности.

Отчёт — диагностика acquisition labels, не независимая оценка боевой политики и не основание менять default. Не обучать по development. По результату отдельно решить, нужен ли учебный набор return-based предпочтений и проверка на нескольких случайных продолжениях. Отрицательные fixed500 результаты не скрывать и не пересчитывать с новым teacher задним числом.
