# Первый supervised опыт головы прицела на native парах

23.10.2026. Фиксируется до приёмки новых альтернативных меток и до fitting. Цель — проверить обучение зависимости поправки от состояния, а не объявить успех по снижению loss.

## Данные и разделение

Объединить4pilot контекста и12новых из уже закрытых16baseline траекторий S4. Проверить provenance двух proof, уникальность (seed,frame), совместимость исходных весов и тип combat_native_aim_pair_labels_v1. Сами метки — только принятые native альтернативы; никаких predicted outcomes вместо labels. Обычный PPO replay этих данных запрещён.

Разделение ранее задано в expansion protocol: максимальный выбранный seed каждой геометрии целиком относится к development holdout. Ожидаются4holdout seed, остальные train. Данные все из registry TRAIN; development holdout не является независимой validation победности. Соседние состояния одного боя не разделяются. До fit требуются16валидных baseline контекстов, минимум3принятых альтернативы на каждый, минимум2train состояния с улучшением относительно baseline и1такое development состояние. Если поддержки нет — зафиксировать нехватку данных, не менять split/порог задним числом.

## Модель и обучение

Начало — исходная S4, не подменённая baseline head. Заморожены actor, value, std, conditional fire, motor/shot predictor и их Adam/RNG/history. Обучается только существующая голова1359→64ReLU→25; архитектура и runtime sampler прежние. Старый head optimizer сбрасывается явно из-за смены задачи. Новый checkpoint получает отдельный supervised scope, несовместимый с продолжением старого B/G/S budget trainer. PPO counters/consumed rollouts не увеличиваются.

Метка состояния: если baseline health damage не хуже всех проверенных действий — предпочтение category0. Если есть строго большее native health damage — равномерное предпочтение среди лучших принятых направлений. Это immediate-damage предпочтение, не доказательство стратегически оптимального действия. Непроверенные направления не помечаются как реальные промахи.

Target distribution =0,1×исходное распределение S4 +0,9×указанное предпочтение. Так остаётся положительная поддержка непроверенных действий и привязка к исходной политике. Loss — mean cross entropy наtrain контекстах, равный вес каждого состояния. Adam, LR0,0003, weight decay0,0001, clip grad norm0,5, ровно200полных шагов. Всё обучение/forward/export checks CUDA. Данные development не используются для gradient, early stopping, выбора checkpoint или изменения бюджета; оценивается только фиксированный endpoint.

Контроль — та же замороженная основная политика с постоянным распределением25категорий, равным среднему финальной обученной head поtrain контекстам. Это сильнее контроля только общей частоты: совпадают и средние предпочтения направлений. Чекпоинт контроля диагностический, head optimizer пустой.

## Проверка endpoint и gate

На train/development показать покрытие проверенных направлений вероятностью, массу на улучшающих/ухудшающих baseline действиях и условную expected health damage среди только проверенных действий. Непроверенные действия остаются неизвестными; их нельзя считать ни попаданием, ни промахом. Это метрики малой целевой выборки, не общая точность или победность.

Короткий native screen допускается, если на development средняя вероятность проверенных улучшающих действий у обученной head больше исходной не менее чем на0,05 и constant control не менее чем на0,02; средняя масса проверенных ухудшающих действий выросла относительно source не больше чем на0,05. Порог не менять по результату. Если gate не выполнен, не запускать расширенную quality confirmation ради положительного результата.

При пройденном gate — sourceS4/trained/constant/rules, по8свежих парных validation условий из того же registry,32native/24CUDA, пул16×2. Offset — первый свободный не ниже33 по доступной истории. Сравнивать цели/смерти/урон, реальные MG outcomes, повороты и неподвижность; ни fit, ни малый screen не меняют default автоматически. Сначала native/CUDA acceptance новой head, затем выводы о качестве. Дальнейшая большая проверка требует отдельного решения на основании результатов.
