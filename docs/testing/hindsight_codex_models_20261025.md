# Проверка Hindsight через подписку Codex, 25.10.2026

Проверены модели через установленный провайдер Hindsight `openai-codex`, а не через отдельный OpenAI API-ключ. База памяти не переносилась в облако; в OpenAI отправлялись тексты фиксированных тестовых задач. Это проверка LLM-провайдера, **не полный тест ingestion/consolidation/knowledge pages**.

## Результаты

Одинаковые девять задач на факты проекта и один двухшаговый тест инструмента. Проверяются точные JSON-типы, значения, отрицания, различение плана и исполнения, неизвестные значения и отсутствие повторного подсчёта боёв.

| Модель | Задачи | Медиана задачи, с |
|---|---:|---:|
| gpt-6-luna, reasoning low | 10/10 | 1.50 |
| gpt-5.6-luna, reasoning low | 10/10 | 1.64 |
| gemma4:12b Q4, прежний локальный прогон | 9/10 | 1.36 |
| batiai/gemma4-12b:iq3, прежний локальный прогон | 8/10 | 1.08 |

Сравнение однопроходное и малое: разница времени между облачными моделями не доказывает устойчивого преимущества. Локальные модели проверялись через Ollama с JSON-режимом и отключённым thinking; облачные — через Hindsight с reasoning low. Контракты провайдеров различаются. Медиана не является задержкой обработки полного документа Hindsight.

`gpt-6.1-luna` была проверена отдельно: HTTP400, `model_not_found`, сообщение о неподдерживаемой модели при авторизации ChatGPT. Автоматической подмены модели не было.

## Исправление адаптера

До исправления обе доступные облачные модели проходили 9 задач на факты, но финальный текст после вызова инструмента терялся. Живой поток содержал `response.output_text.delta`; `_parse_sse_tool_stream` установленного Hindsight обрабатывал только старое `response.text.delta`. При этом сервер сообщал ненулевое количество выходных токенов, а адаптер возвращал `content=null`.

В установленной копии `codex_llm.py` добавлена поддержка обоих имён событий только в парсере инструмента. Оригинальный файл сохранён. Синтетическая регрессия проверяет оба имени, отсутствие удвоения текста при итоговом message item и сохранение аргументов инструмента; 3/3 проверки пройдены. После этого обе модели повторно прошли полный набор 10/10.

Первая попытка правки попала в другой парсер и удвоила обычный текст; этот прогон сохранён как отрицательный технический результат (`codex-6luna-sse-fixed-20261025-v1`, 0/10). Правка скорректирована, этот результат не считается качеством модели. Патч установленного пакета локальный и может быть потерян при обновлении зависимости.

## Авторизация и состояние сервиса

Для коротких тестов использовалась отдельная временная копия только действующего access token, без refresh token. Основной файл авторизации Codex не изменился; временный файл удалён в finally. Секреты не записывались в результаты. Для постоянного фонового использования нужен отдельный вход в профиль Hindsight, чтобы обновление токенов не конфликтовало с интерактивным Codex.

По запросу пользователя Gemma выгружена, worker Hindsight отключён (`HINDSIGHT_API_WORKER_ENABLED=false`). API и PostgreSQL остаются локальными. Постоянный LLM-провайдер памяти на Codex пока не переключён; автоматическое создание сводок не возобновлено. Модель может загружаться при явном LLM-запросе к текущей конфигурации, поэтому Reflect и обработку очереди до переключения не запускать.
