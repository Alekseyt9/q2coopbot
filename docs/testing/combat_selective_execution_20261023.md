# Выбор действий при исполнении: ограниченный screen

Цель — проверить, уменьшает ли случайный выбор цели и режима прицела эффективность уже обученной политики. Полный deterministic ранее ломал смену оружия в recovery; эту ошибку не повторяем.

Два явно обозначенных inference-only режима:

- `greedy_target_mode_v1`: argmax обученных target и aim-mode logits.
- `greedy_target_mode_fire_v1`: то же, плюс решение о выстреле по знаку итогового conditional-fire logit сети.

Weapon, pose, Gaussian movement/aim остаются стохастическими. Даже заменённые решения расходуют свои прежние uniform draws: последующие случайные числа не сдвигаются. Все параметры actor/value/std, Adam/RNG/history сохраняются. Контрактный Go-тест проверяет маски, argmax, ties, запрет несовместимых режимов и совпадение RNG для 1000 последовательностей; нейросеть на CPU не исполняется. CUDA helper сверяет численные тензоры и запечатывает копии.

Это изменение способа исполнения политики, а не обучение и не новый набор весов. Здесь нет удержания цели таймером, правил ведения боя или внешней маски огня. Стандартная log-probability в native sample остаётся контрфактической; такие captures запрещены для обычного PPO export/training/replay. Python validator и Go eligibility отказывают; evaluator дополнительно запрещает их CUDA PPO replay.

Протокол до запуска: восемь validation условий base3/ware2 (две точки, ordinary/recovery). Четыре варианта: исходный `combat-conditional-fire-zero-v1-20261022`, две inference копии и rules. Всего 32 native боя, один пул 16 ×2; парные варианты имеют одинаковые условия/сиды. Восемь исходных stochastic captures дополнительно проверяются CUDA replay; две mixed execution копии — только native audits, без ложной PPO-проверки. Подготовка v1 остановилась до native: широкий glob включил 20 JSON, не являющихся планами. Их исключили, offset758 зарезервировали; реальные бои проведены v2 с offset759.

В первую очередь сравниваем победы, смерти и урон; затем повороты, target switches и stationary-clear frames. Восемь боёв на вариант — отбор гипотезы; automatic promotion запрещён, окончательное превосходство над rules такой объём не доказывает.

## Результаты малого screen

`combat-selective-execution-screen-v2-20261023/complete.json`: 32 native/8 CUDA, процесс завершился с кодом 0. Ownership, target/weapon/execution audits завершены. Веса неизменны; новый default не выбран.

| Вариант | Победы | Убийства | Нанесённый / полученный урон | Смерти |
|---|---:|---:|---:|---:|
| Start |5/8|15|2364 / 503|3|
| Target + mode |5/8|13|2345 / 454|3|
| Target + mode + fire |6/8|14|2368 / 382|1|
| Rules |5/8|12|2034 / 549|3|

Target+mode не изменил исходы. Target+mode+fire дал одну дополнительную победу без потерянной относительно start и rules; этого недостаточно для приёмки.

| Метрика исполнения | Start | Target+mode | Target+mode+fire |
|---|---:|---:|---:|
| Большие yaw commands |4,96%|2,98%|2,80%|
| Stationary при clear enemy |14,87%|23,83%|19,63%|
| Смены target на 100 кадров |10,65|7,77|7,64|
| Attack commands без target |9,00%|8,96%|26,62%|
| Начальная задержка attack command, frames |2,125|2,125|2,250|

Команды attack не равны реальным выстрелам. Для inference-only вариантов отчёты MG теперь могут явно использовать сохранённый `dataset/steps.jsonl` native capture, без PPO replay. Восемь source случаев сверены с прежним CUDA-verified export: множества eligible windows и все измерения 320 shots совпали точно (`native-dataset-parity.json`). Сохранены проверки provenance, release generation, alive first life, exclusive matched provider window и отсутствие recovery. Это анализ телеметрии без NN inference/training, а не обход запрета на PPO.

| Реальные MG shots | Start | Target+mode | Target+mode+fire |
|---|---:|---:|---:|
| Live monster damage / все выстрелы |209/320|210/320|213/315|
| Solid contact |101|108|94|
| Corpse contact |10|2|8|

Доля полезных MG shots выросла с 65,31% до 67,62%; стрельба в геометрию остаётся. Поворотов меньше, но stationary-clear стало больше. Поэтому гипотеза допускается только к расширенной проверке, не к promotion.

Следующий заранее ограниченный development confirmation: три варианта start/target+mode+fire/rules, по 24 свежих боя (три сида на каждое из восьми условий), 72 native/24 CUDA, один пул 16 ×2. Исходные веса и сцены прежние; новые сиды, без fitting и automatic promotion. Это ещё не проверка на неизвестных картах.

## Расширенная проверка завершена

`combat-selective-execution-confirmation-v1-20261023/complete.json`: 72 native/24 CUDA, offset760, по три сида на условие. Процесс завершился с кодом 0; все execution/ownership/weapon/target audits и CUDA replay исходной политики завершены. Два смешанных режима по-прежнему не использовались как PPO-данные.

| Вариант | Победы | Убийства | Нанесённый / полученный урон | Смерти |
|---|---:|---:|---:|---:|
| Start |12/24|38|6923 / 1447|9|
| Target + mode + fire |14/24|40|7140 / 1569|9|
| Rules |18/24|47|7641 / 1509|6|

Относительно start: четыре полученные и две потерянные победы. Относительно rules: три полученные и семь потерянных. Небольшой выигрыш по числу побед не сопровождается выигрышем по полученному урону или смертям; превосходства над rules нет. Кандидат отклонён для default/promotion.

Large-yaw commands 5,14% → 3,89%; смены target 10,49 → 7,63 на 100 кадров; stationary-clear 19,30% → 23,84%. Начальная задержка attack command 5,29 → 4,75 кадра. Доля attack commands без target 22,07% → 10,06% не означает сокращения реальных промахов.

Реальные MG shots: live monster damage **443/674 → 458/706** (65,73% → 64,87%); solid contact **207 → 234**; corpse **22 → 13**; sky 1 → 1. Targetless shots **21 → 41**; у кандидата один из них нанёс урон живому монстру. Поэтому ранний результат «17 → 3» на восьми боях не подтвердился на новых сидах. Выстрелы в геометрию остаются проблемой.

Практический результат: argmax категориальных действий действительно сокращает смены цели и большие повороты, но не решает качество прицеливания и может увеличивать неподвижность. Не переносить этот небольшой screen на весь campaign или неизвестные карты. Следующий опыт должен изолировать шум собственно yaw/pitch от выбора огня и оружия; до него проверить историю уже выполненных aim-noise экспериментов и не повторять закрытые варианты вслепую. Default остаётся прежним.
