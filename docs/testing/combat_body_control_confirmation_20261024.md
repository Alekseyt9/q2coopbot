# Независимая проверка контроля после body-input опыта

24.10.2026, закрыта около 15:52 МСК. Превосходство над rules не подтверждено; основной набор весов не заменён.

## Условия

Контрольная ветка выбрана после просмотра малого body screen: 7/8 целей против 5/8 rules. Это новая проверка постфактум замеченного результата; отрицательный вывод самого body-input опыта не пересматривается. В независимую партию не входит дообучение или выбор другого checkpoint.

Протокол `docs/combat_body_control_confirmation_protocol_20261024.json`; spec `docs/combat_body_control_confirmation_spec_20261024.json`. Артефакты `workspace/artifacts/combat-body-control-confirmation-workflow-v1-20261024`.

24 рецепта на base3/city1/jail1/ware2, две точки на карте, пары/тройки противников, обычные и recovery loadout. Три варианта: initial ablated, final ablated после четырёх обновлений и rules. Всего 72 native / 48 CUDA, общий пул до16, timescale2, без fitting. Новизна confirmation offset16 проверена по полной физической истории 5735 task plans перед играми.

Порог до запуска: кандидат должен выполнить минимум на3 цели больше rules и на1 больше initial; смертей не больше обоих; полученный HP урон не выше110% обоих; управление видимым боем принадлежит модели. Автоматического promotion нет.

## Исправление истории сидов после закрытия опыта

Обнаружено, что evaluator автоматически проверял лишь верхний уровень artifacts, а collector — несколько фиксированных шаблонов глубины. Полный список приходилось передавать извне. Этот опыт получил такой список до запуска и остаётся свежим; для уже закрытого body опыта полный повторный audit также показал нулевое пересечение TRAIN/evaluation с остальной сохранённой историей.

Добавлен общий `scripts/combat_plan_history.py`; evaluator и collector теперь используют рекурсивный поиск физических планов с исключением текущего output root. Directory symlinks и NTFS junction/reparse aliases не обходятся. Неисполняемые JSON списки с plan в имени пропускаются, повреждённая/отсутствующая явно заданная история и неверные типы сидов отвергаются. История не подменяется пустой при ошибке чтения.

Четыре metadata regression tests прошли, включая настоящее directory symlink exclusion. Реальный prepare-only с пустым explicit history сам нашёл использованный вложенный план и завершился ожидаемым `Historical seed reused`, до игр и NN вычислений. Доказательство: `combat-history-autodiscovery-regression-v1-20261024/regression-result.json`. Полная физическая инвентаризация сохранённых файлов проверяется отдельно; оптимизация поиска не меняет seed semantics и не требует NN тестов на CPU.

Полная проверка текущего discovery нашла5785 файлов и сохранила все5770 путей прежнего rg inventory; различие — новые preflight планы. Сканирование с исключением текущего output заняло103.247с на этом диске. Это проверка полноты, не доказанный speedup; полный обход большого artifacts остаётся заметной ценой подготовки. Артефакт `combat-history-physical-inventory-optimized-20261024.json`. После локального упрощения обработки обычных файлов четыре unit tests повторно прошли. Go/NN код на этом шаге не менялся.

## Следующая работа

1. На уже собранных собственных TRAIN боях контрольной ветки связать входящий native урон с состоянием **до команды**, фактически применённым движением, видимыми противниками и выстрелами. Использовать существующий проверенный native effect/window audit; не переносить скрытые native поля в policy.
2. Разделить источники входящего урона и ситуации: неподвижность, отменённое движение, движение под огонь, потеря контакта/стрельба по памяти. Такие разрезы описательны; действие в том же окне не обязательно вызвало попадание уже летевшей пули.
3. Сопоставить найденные ситуации с уже имеющимся TRAIN advantage-credit разбором. Он уже показывает отрицательный средний advantage у неподвижных строк четвёртого раунда; утверждать без проверки, что награда прямо поощряет стояние, нельзя.
4. Только после конкретного механизма зафиксировать новую гипотезу и равный бюджет с собственным fresh screen. Уже отрицательные miss-cost, center/vertical, body-input, fire-only, короткий underfire horizon и curriculum варианты не повторять как новые идеи без отличия механизма.

Нового fitting после этого отрицательного confirmation не запущено. Цель устойчиво превзойти rules, эффективный бой, прохождение кампании и human coop остаётся открытой.
