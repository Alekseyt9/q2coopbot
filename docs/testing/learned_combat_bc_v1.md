# Первый пилот behavior cloning

05.10.2026. R4a частично реализован: обучены веса, Go исполняет ту же сеть, выполнена offline-проверка. Тактическая приёмка и PPO отсутствуют. Последующее [самостоятельное исполнение BC v1](learned_combat_bc_direct_v1.md) провалило боевую проверку; веса не подходят для замены правил. Результаты ниже относятся к ограниченным упражнениям существующего харнеса.

## Данные и контракт

`cmd/q2bc-data` объединяет три ранее замороженных набора после повторной проверки исходных трасс, native Step/Effects/Reward/reset и SHA файлов. Повторение seed между наборами запрещено. Артефакт: `workspace/artifacts/combat-bc-data-full-v1-20261005`.

| combat-demonstrations-20261005-220948-165/dataset | 12700–12711 | Только jump/crouch/release |

Всего 36 эпизодов: train 24 / validation 6 / test 6, соответственно 757 / 260 / 211 кандидатов. Маски не превращают отсутствие метки в отрицательный пример: movement и aim обучаются только там, где отбор их разрешил; отрицательные attack не обучают aim; вертикальные примитивы не обучают горизонтальное движение. Положительных aim/attack всего 36; attack/release 216; вертикальных меток 48. Части повторяют одну геометрию и простые упражнения, поэтому разделение по seed не доказывает перенос на новые условия.

`internal/policy/features.go` задаёт `combat_features_v1`: 386 чисел, только UDP-наблюдения, без seed, frame/actor ID, награды и будущего состояния. Вход содержит здоровье/броню, собственную скорость и взгляд, предыдущую команду, оружие/патроны/фазу оружия и свежесть инвентаря; BSP-пробы стен, высоты и перепадов; до 8 врагов и 4 снарядов с относительным положением и оценённой скоростью; напарника; по 4 ближайших предмета и объекта; по 4 наблюдаемых mover и beam; краткую историю 4 кадров. Положения преобразуются относительно взгляда, числовые значения нормализованы и ограничены [-4,4]. Доступность геометрии, оценок скорости и групп объектов имеет маски; неизвестный clear-shot пока свёрнут в false. Это фиксированное подмножество observation v3, а не полный контракт целевой политики.

## Обучение и устройство

`scripts/train_combat_bc.py` — отдельная offline-утилита PyTorch; игровой клиент и исполнение остаются Go. Сеть: 386 → 64 ReLU → 64 ReLU → 8. Выходы: tanh forward/side/yaw/pitch, attack logit, три logits release/jump/crouch. Головы оружия, value и PPO ещё нет.

До обучения заморожен `scripts/scenarios/combat-bc-v1.json`: seed 20261005, 300 full-batch шагов Adam, lr 0.001, финальная эпоха без выбора по validation/test. Loss: masked MSE движения/прицела + BCE attack + CE вертикального действия. Вес положительного attack 6; веса вертикальных классов [0.6667, 1.3333, 1.3333], вычислены только на train. Test оценён после фиксированной финальной эпохи; он не использовался для настройки.

Найден существующий `F:/src/strat/.venv-gpu/Scripts/python.exe` с PyTorch 2.10.0+cu128 и RTX 5070. Общая среда прочитана без установки пакетов в неё. Утилита сравнивает CPU и CUDA на фактическом masked batch: 10 прогревочных + 50 измеряемых шагов Adam, CUDA синхронизирована. CPU 2.331 мс/шаг, CUDA 5.664 мс/шаг: здесь CPU быстрее в 2.43 раза и выбран автоматически. Это сравнение данной маленькой сети, включая маски, а не оценка GPU для большого обучения. После сравнения модель и seed созданы заново. Сами 300 шагов заняли 0.681 с, без старта Python, benchmark и экспорта.

До требования скачивать только на F была отдельно создана локальная CPU-среда `workspace/build/combat-training-env`; текущие веса обучены существующей CUDA-средой. Последующие загрузки и кэши должны находиться на F. Утилита заранее направляет TMP/TEMP, pip/Torch/CUDA/Triton/XDG cache в `workspace/build/training-cache`. Для повторения не требуется загрузка нового CUDA-пакета.

## Go и проверки

`internal/policy/mlp.go` загружает ограниченный JSON с проверками версии, форм слоёв, весов, неизвестных полей и хвоста файла. Веса загружаются один раз, версия политики содержит SHA. Решение формирует свежий action и проверяется существующим контрактом команд; выбора оружия нет. Обычный live-клиент автоматически на сеть не переключается.

`cmd/q2bc-eval` пересчитывает признаки из полных observation и сравнивает все 1228 forward outputs с PyTorch: max absolute error 0.000002062, допустимый предел 0.0001. Для каждого примера также прошёл Decide/Command. Первое одиночное измерение времени имело нулевой median из-за дискретности Windows-таймера; оно не используется как доказательство нулевой задержки. Тесты проверяют ошибочные формы/веса/версии/JSON, запрет решений для мёртвого наблюдения, nonfinite признаки, отсутствие ID во входе и отличие неизвестного значения от известного нуля.

Отчёт первой offline-проверки: `workspace/artifacts/combat-bc-weights-v1-20261005-r1/go-parity.json`. Повторное измерение `go-parity-batched.json` усредняет 32 Decide на каждом observation, чтобы превышать дискретность таймера: p50 79.91 / p95 110.28 / p99 126.14 / max 143.73 мкс на решение. Это амортизированное время внутри batch, а не хвост одиночного вызова. Parity осталось тем же; веса не переобучались.
