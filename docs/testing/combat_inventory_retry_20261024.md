# Повторная отправка инвентаря вместе с frozen-world кадром — 24.10.2026

Цель — достоверные причинные сравнения действий для последующего улучшения обучаемого боя. Исправление транспорта само по себе не доказывает рост боевого качества.

## Проблема и механизм

В contact-movement пилоте нашлось различие **до** интервенции: base3 seed1164165204, действие менялось с кадра227, но уже на129 было Bullets18/17 и inventory_age1/0; менялись features20/827, latent и команда. RNG seed и recurrent memory одинаковы. Свидетельство `combat-memory-contact-inventory-race-witness-v1-20261024`.

Нативный сервер при удержании frozen-world вызывает SV_SendClientMessages повторно без игрового тика. Игровой ClientEndServerFrame формирует svc_inventory в одноразовом datagram. Первая отправка кадра очищает datagram; следующий снимок того же мира мог уже не содержать инвентарь. После потери первого UDP-пакета клиент способен получить новый кадр с инвентарём предыдущего. Отдельной сетевой записи исходной потери нет, поэтому именно потеря конкретного старого пакета не объявляется доказанной; механизм подтверждён исходным кодом и проверяется принудительной потерей на исправленном сервере.

## Изменения

В `F:/src/quake2/yquake2`:

- `src/server/header/server.h`: отдельный клиентский кэш полного svc_inventory, привязанный к spawncount и framenum; старый кэш не переносится в новый мир.
- `src/server/sv_game.c`: только в loopback cheat harness lockstep полный inventory unicast сохраняется в кэше, а не в одноразовом datagram.
- `src/server/sv_send.c`: каждый снимок этого frozen кадра, включая повтор, содержит его инвентарь после svc_frame. Другие эффекты остаются одноразовыми. При необходимости reliable-блок отправляется отдельно. Если кадр с текущим инвентарём не помещается, тест явно завершается ошибкой вместо выдачи устаревших данных.

Протокол обычного svc_inventory и Go-декодер не менялись. Вне изолированного lockstep сервера прежний путь сохраняется. Веса actor/critic, признаки, конфиг пользователя и награда v13 не менялись.

Добавлен явно включаемый harness fault `sv_test_inventory_drop_once_frame`: пропускает первую отправку указанного кадра один раз на клиента; повторный frozen снимок должен доставить и мир, и актуальный инвентарь. Он доступен через `-InventoryDropOnceFrame` в существующих run_learned_combat_baseline.ps1/run_solo_tactical_retreat.ps1, только при Synchronous. Диагностический сбор маркируется ordinary_training_eligible=false. По умолчанию выключен.

Сборка: `cmake --build F:/src/quake2/yquake2/build/codex-speed-test --target q2ded --parallel 8`, MinGW из F:/src/quake2/buildenv/pkg/buildenv/mingw64/bin. Собрана успешно. Существующие runtime инструменты устанавливают новый бинарный файл через отдельный immutable snapshot; старые записи не перезаписывались.

## Доработка для больших снимков: компактный inventory v2

Первый refreshed32корпус остановился, не был принят: в jail1 seed1174165208 кадр136 требовал927байт мира+513байт inventory при доступных1365байтах. Это реальная вместимость пакета, не ошибка обучения. Весь неполный корпус `combat-memory-contact-refresh-corpus-v1-20261024` исключён, пригодное подмножество по исходам не выбиралось.

В isolated lockstep теперь используется компактный полный replacement: только ненулевые слоты, каждая запись — slot byte + little-endian signed count short, кодированные hex, с явными spawncount/frame. Он передаётся стандартным svc_configstring в последнем general slot2079, префикс q2inv1. Пакет остаётся protocol34, обычные клиенты игнорируют эту служебную строку. Go-декодер проверяет поколение, номер кадра, длину, hex, порядок/уникальность слотов, ненулевые записи и заменяет inventory атомарно, обнуляя отсутствующие слоты. Если компактная запись длиннее стандартных513байт, остаётся полный стандартный svc_inventory; он по-прежнему находится в том же world packet. Для текущих тестовых loadout компактный вариант существенно меньше.
