# Следующая проверка: 16 против 64 посильных учебных боёв

Исходник — фиксированный U1, веса SHA-256 `21c3b680e0b6090d601d524f6da53d73ae6dd083c8e7a9a6da2e6d268ccadd26`. Независимая проверка U1 дала 17/24 против 13/24 у родителя и 19/24 у правил. Это основание для следующих опытов, а не объявление превосходства над правилами. U2 и equal-mass ранее не подтвердили улучшения.

Гипотеза: обновления по 16 боям недостаточно покрывают состояния боя, поэтому следующий полный update может сильно зависеть от небольшой выборки. Сравнить 16 и 64 собственных on-policy боя от одного checkpoint/Adam, при одинаковых наградах, конфигурации и числе шагов. Взвешивание по кадрам прежнее; отклонённый equal-mass здесь не используется. Все ветви политики остаются обучаемыми. Не вводятся правила выбора оружия, движения или наведения.

## Предварительная подготовка

Рабочий root: `workspace/artifacts/combat-beginner-batchsize-v4-20261027/`; `prepare.py` выполняет только метаданные и проверку планов, не игры и не обучение. TRAIN кандидаты 112–191, validation 384–463, по 80 кандидатов на descriptor. Все условия проходят существующий `beginner_visible_resources_v2`, ранее употреблённые сиды исключаются по checkpoint.

Найдено 106 ресурсно и геометрически допустимых TRAIN-условий на 17 картах; после исключения 12 употреблённых — 94. При ограничении четыре боя на карту доступны только 45 мест до исключения употреблённых, поэтому 64 так собрать нельзя. При лимите 10 после исключения употреблённых остаётся 61 место. **До новых игр** лимит изменён на 12, без изменения критериев сложности и без просмотра исходов; выбранный набор остаётся распределённым по 17 картам. Эта неоднородность состава должна учитываться в интерпретации результата.

Из 64 условий детерминированно выбирается вложенный поднабор 16: приоритет картам с меньшим числом уже выбранных боёв, затем descriptor, затем seed. Выбор зависит только от плана. Поднабор должен покрыть 16 разных карт. Исходы боёв не используются. Артефакт `train/small-selection.json` связывает список сидов с SHA родительского плана.

Ранние metadata-only попытки сохранены: v1 обнаружила некорректное предположение «число descriptor не меньше числа боёв», v2/v3 — недостаточную вместимость при лимитах 4/10. Новых игровых затрат и fitting в них не было. Их не следует перезапускать или выдавать за прерванные игровые прогоны.

## Допуск поднабора

Старый `combat_full_joint_train_request_v1` по-прежнему требует все случаи исходного TRAIN-плана. Реализован отдельный `combat_full_joint_subset_train_request_v2`: он сохраняет исходный полный plan/pool и их хеши, требует `selection` и `selection_sha256`, проверяет manifest и воспроизводит выбор только из условий. Затем требует все и только выбранные случаи. V1 с полями поднабора отклоняется, обычный V1 с пропущенным случаем также отклоняется. Привязка к настоящему pool plan SHA, fixture, модели, CUDA proof и consumed history не обходится.

Модуль `scripts/combat_train_subset.py` не использует исходы, награды или качество модели. Он проверяет точную схему manifest, исходный plan SHA, допустимое число случаев и воспроизводимость сидов. Порядок задач и экземпляров в плане не влияет на выбор.

Проверка `combat-train-subset-check-v1-20261027/report.json` прошла: настоящий старый корпус из 16 случаев принят целиком; детерминированный поднабор 8 из него принят с исходными native/CUDA доказательствами. Отклонены 13 неверных запросов: подмена manifest/seed/count/hash, поля результата, пропущенные или посторонние случаи, употреблённый seed и попытка использовать subset через V1. Отдельно подтверждено точное воспроизведение замороженного будущего поднабора 16 из 64. Это проверка метаданных и допуска, без нейросетевых вычислений на CPU.

64 боя собираются один раз; оба fitting используют общие реальные записи. Neural replay, оба fitting и проверки checkpoint/resume — только CUDA.

## Предварительный бюджет и оценка

64 TRAIN native / 64 CUDA, затем 24 новых оценочных условия: U1, update16, update64, правила — 96 native / 72 CUDA. Всего 160 native / 136 CUDA, пул 16 инстансов ×2. Ни validation, ни прошлые диагностические потери не попадают в TRAIN. До окончания metadata-preflight новых игр не запускалось.

Малый опыт сравнивает конкретные вложенные наборы, поэтому сам по себе не доказывает универсальный эффект размера batch: состав и конечная выборка тоже могут влиять. Положительный результат потребует независимого подтверждения. Автоматического продвижения нет.

## Живой запуск

Исполняемый root: `workspace/artifacts/combat-beginner-batchsize-run-v1-20261027/`, `run.py`. Он использует неизменные планы и manifest из preflight v4, проверяет их настоящим Go planner и фиксирует код/данные до игр. Сбор 64 TRAIN запущен в существующем пуле 16 ×2; ранняя проверка подтвердила 11 завершённых случаев. Не перезапускать живой runner и не менять canonical Go/Python/PowerShell во время цепочки.

Далее автоматически: 64 CUDA replay, два fitting в `fit-small` / `fit-large` от одного U1/Adam с одинаковым config, независимый CUDA-аудит обоих checkpoint и точной вложенности употреблённых rollout, затем source/small/large/rules на 24 новых условиях. Для большого набора заранее записаны критерии: +2 победы к U1, +1 к small, не меньше правил, смертей не больше каждого контроля, урон не выше 110% правил. Результатов качества на момент запуска нет.

## Корпус собран, началось обучение

64 native TRAIN завершены, все capture/provenance checks прошли. `train/capture-summary.json` фиксирует исходную U1 на этом учебном наборе: 47 завершённых целей, 8 смертей, 9 незавершённых боёв; 1298 HP полученного урона, включая 290 HP самоурона. Это native goal flags до отдельного ownership-аудита, а не оценка новых весов и не новые независимые оценочные победы.

Все 64 записи прошли CUDA replay. `fit-small` завершён: 1900 переходов, 8 actor steps, KL 0,00855, полный Adam продолжен от U1, global update 11. Веса SHA-256 `891a2bd33917d25abf20aaf57413819f56531022b4a3dac4b639f7c3b9598c98`, checkpoint `1e7ae6dac6311265304e56f4f296e4b02a897a0a531c05fe6e4890ff665e42ad`. Это fitting, не доказательство качества. Начался `fit-large`; последующая оценка должна оставаться неизменной.

`fit-large` также завершён на CUDA: 7259 переходов, те же 8 actor / 8 critic steps, KL 0,00621. Веса SHA-256 `169bc21e96cf0e6352adc27cbcd85cc811923391f8e0b0f774d169edff081603`, checkpoint `7a89e09d30b14fb067b39a748261827ddce7c98a1494017f6bbad8c144d8c947`.

Независимый `fit-audit.json` прошёл: оба checkpoint повторно загружены на CUDA; исходные config/layout Adam совпадают, parent и consumed prefix сохранены, новые rollout малого набора являются точным строгим подмножеством большого. Frozen geometry/hints сохранены. Это подтверждает корректность сравнения fitting, а не превосходство одного варианта. Запущена оценка 96 боёв на зафиксированных 24 новых условиях.

## Оценка закрыта: 64 боя не дали улучшения

Всего завершены 160 native / 136 CUDA. Независимые validation, ownership и quality audits прошли; все засчитанные победы трёх моделей автономны. Две незавершённые передачи управления в проигранных траекториях сохранены, победами не считаются.

|---|---:|---:|---:|---:|---:|
| Исходная U1 | 16 | 4 | 600 | 111 | 59 |
| Update16 | 19 | 3 | 728 | 290 | 119 |
| Update64 | 16 | 6 | 612 | 192 | 59 |
| Правила | 23 | 1 | 178 | 0 | 0 |

Все пять критериев update64 не выполнены. Относительно U1 у него одна новая победа jail1 и одна потерянная waste1, итог без прироста и с большим числом смертей. Update16 получил четыре новые победы и потерял fact1; больше побед сопровождалось ростом полученного урона и самоурона. Ни один новый вариант не продвигается. Результат не доказывает, что увеличение любых будущих корпусов бесполезно: сравнивались конкретные вложенные наборы с неравным распределением карт.

Затраты завершённых фаз из process receipts: native TRAIN 256,4 с, TRAIN CUDA 161,4 с, update16 24,5 с, update64 58,7 с, отдельный аудит checkpoint 6,7 с. Это полное время фаз с запуском процессов, чтением и проверками, не время GPU kernels. Записи: `completed-phase-costs.json`.

Read-only проверка реестра обнаружила 204 random-roster descriptor на 38 картах, тогда как предыдущая серия использует 53 TRAIN descriptor. В её 38 validation IDs есть четыре пересечения с TRAIN, поэтому вне объединения этих списков остаётся 117 descriptor на 33 картах. Они не объявляются глобально не виденными: перед включением надо проверить остальные исторические протоколы. Эти дополнительные descriptor в обучение пока не добавлялись. `registry-coverage-audit.json` сохраняет список и границы утверждения.

Следующий отдельный шаг — диагностика самоурона гранатой на текущей U1. Выбраны четыре собственных TRAIN-корня по наблюдениям, а не по исходам; источник/release сравниваются по двум холодным повторам, меняется только attack bit одного кадра. Это сбор диагностических причинных данных для возможного следующего метода обучения, не автоматическое правило отпускания и не повторный ordinary PPO fit. Root: `combat-beginner-grenade-pair-selection-v1-20261027/`, native: `combat-beginner-grenade-pair-native-v1-20261027/`, audit: `combat-beginner-grenade-pair-audit-v1-20261027/`.

## Дополнительная причинная диагностика закрыта

16 native / 16 CUDA завершены, 48/48 проверок префикса, холодных повторов, исходного поведения и единственного изменения attack bit прошли. Выбраны первые подходящие наблюдаемые состояния текущей U1 на bunk1 / mintro / fact1 / fact2; исходы при выборе не читались. Все четыре выбранных корня оказались на кадре 109, поэтому это особенно узкий ранний этап удержания гранаты.

| Сцена | Source цель / смерть / самоурон HP | Release цель / смерть / самоурон HP |
|---|---|---|
| bunk1, 1832000151 | да / нет / 44 | да / нет / 34 |
| mintro, 1859000120 | нет / да / 0 | нет / да / 43 |
| fact1, 1874000127 | да / нет / 43 | да / нет / 0 |
| fact2, 1877060155 | нет / да / 55 | да / нет / 65 |

На четырёх мирах цели 2→3, смерти 2→1, полученный урон 267→221 HP, самоурон **142→142 HP**, убийства 4→6. Коррелированные повторы не считаются дополнительными мирами. Вмешательство помогает в отдельных сценах, но не является универсальным безопасным действием. В частности, на mintro release добавил самоурон, а на fact2 дал победу при большем самоуроне.

Диагностические записи помечены `combat_diagnostic_grenade_release_rollout_v1`, не допускаются к ordinary PPO и не объявляются готовыми preferred-action labels. Новой обученной политики в этом опыте нет. Следующая возможная гипотеза — обучение условному выбору по реальным парным последствиям действий, но сначала нужны более разнообразные времена удержания и ситуации, целые миры должны разделяться между fitting и проверкой. Четыре одинаковых по времени корня недостаточны для вывода об обобщении и не оправдывают правило отпускания на кадре 109.
