# Веб-воспроизведение DM2

В Run Explorer добавлен режим «Демо 3D» рядом с обычной картой. Он читает настоящую `.dm2` выбранного прогона, а не восстанавливает ракурс по направлению JSONL-траектории. Доступны выбор записи/карты, пауза, перемотка и прежние скорости. Прогоны без демо продолжают отображаться на карте.

Go декодирует протокол34, включая полные/дельта-кадры, player viewoffset, viewangles/FOV, HUD и видимые сущности. Незавершённый последний пакет живой демки не воспроизводится; полностью прочитанные кадры доступны. Кеш декодированных записей обновляется по размеру/mtime и хранит до8 файлов. API разрешает только соседние с зарегистрированным JSONL файлы `<имя-трейса>.dm2` и `<имя-трейса>-*.dm2`; пути через symlink проверяются относительно каталога artifacts.

BSP-геометрия включает полы, стены и потолки, с раздельными inline-моделями дверей/платформ. Она кешируется по файловой сигнатуре карты и отдаётся с gzip/ETag. Браузер хранит геометрию в WebGL-буферах, с перспективой от записанной камеры, простым освещением, контурами и туманом. Сетевые inline-объекты перемещаются по кадрам демо. Монстры отображаются красными фигурами, предметы зелёными, прочие объекты жёлтыми. Их позиции записанные, внешний вид условный.

Границы реализации: нет текстур, MD2-анимаций, звука и точных визуальных эффектов движка; ориентация условных фигур и inline-моделей использует yaw. Это упрощённый просмотр прогона, не полный порт Yamagi. Произвольный `output.demo_dm2` вне соседних имён пока не обнаруживается автоматически.

Монстры в подтверждённой death-анимации стандартных моделей baseq2 исключаются из объектов воспроизведения. Используется общая таблица `quake.MonsterDead`; несолидность сама по себе не означает смерть. Классификация пересчитывается для каждого кадра, поэтому перемотка назад, оживление медиком и повторное использование entityID не скрывают живую сущность навсегда.

Дополнительно проверен узкий экран390×844: перемотка/play/пауза/возврат на карту без ошибок и вертикальной прокрутки. Живой UDP smoke новой сборки Go-бота на отдельном порту31995:29 кадров/29 команд, decode_errors=0. HUD проверен на реальном снимке WebGL; inventory/objectives не перекрывают сцену.

Чёрные грани исправлены расчётом нормали по всему полигону методом Newell: у384 граней base1 первые три вершины коллинеарны, из них372 относятся к миру. Нормаль по первой тройке была нулевой и давала чёрную заливку в shader. На одном и том же наблюдении121 число чёрных пикселей WebGL уменьшилось с90815 до0 из652992; ошибок GL нет. Регрессия: `node scripts/test_demo_geometry.cjs` проверяет пол/стену с коллинеарным началом, обратный порядок вершин, полностью вырожденный полигон и нормали в загружаемых буферах.

Проверка на записи base1-demo-20261006-200126/run/bot.dm2: 643 кадра, камера первого кадра [128,-320,64], yaw135°, FOV90; 7905 граней base1. Chromium: режим3D, перемотка на наблюдение121, продвижение кадров при play, пауза и переключение обратно в2D, без ошибок JavaScript и вертикальной прокрутки на1600×1000. Unit-тесты проверяют камеру/HUD, границы API, ETag, обновление незавершённой демки, неверную длину пакета, 48-байтовые dmodel и включение вертикальных граней.
