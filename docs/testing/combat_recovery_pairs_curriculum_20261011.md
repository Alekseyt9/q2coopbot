# Более лёгкие бои для обучения выбору оружия

Закрытый опыт recovery-троек не дал пригодных для продвижения весов: parent35→35, shared33→25 побед из112; на recovery только1→1 и1→2 из32. CUDA-проба показала98,39–98,72% вероятности keep при начальных Grenades. См. `combat_grenades_recovery_native_results_20261011.md`.

В основной реестр добавлены восемь отдельных рецептов: parasite+infantry, по две исходные точки base3/city1/jail1/ware2. Геометрия проверяется существующим BSP-генератором. Стартовый инвентарь прежний: Grenades5 в руках, Machinegun40, Shotgun20, Blaster; автомат не выбирается принудительно. Сиды новых пар отделены от всех прежних семейств и всех split. Проверены588 диапазонов реестра. Старые рецепты и оценки сохраняются.

Первый этап —64 диагностических боя: восемь семейств × четыре validation-сида × исходный parent и rules. Пул16 ×2. Это проверка сложности нового curriculum до изменения обучения, а не confirmation обновлённой модели. Исходный parent берётся из закрытого equipped-balanced обновления, не из отклонённого recovery обновления. Confirmation offset12 старого сравнения не используется для обучения.

Далее при годных данных: явная CUDA-ветка исследования оружейных действий с собственным сбором новых train-боёв, сохранением остальных голов и проверкой optimizer/history; full-actor обучение на собственных данных; парная confirmation с прежними боями для контроля регрессии. Изменение температуры/энтропии ещё не реализовано. Любое изменение вероятностей требует нового собственного корпуса, нельзя пересчитать поведение старых trace и считать их on-policy.

Артефакты генерации и локального малого реестра: `workspace/artifacts/combat-grenades-recovery-pairs-generated-v1-20261011.json`, `combat-grenades-recovery-pairs-registry-v1-20261011/index.json`. Итоги живого64-бойного этапа фиксируются после закрытия, генерация рецептов сама по себе не доказывает исполнимость или улучшение качества.

## Живой этап закрыт

64/64 нативных боёв, ошибок0, source_unchanged=true,165,735с. Закрыты32 CUDA-воспроизведения собственных историй модели:5157 кадров, без обучения. По картам parent/rules: base3 3/8 и8/8, city1 3/8 и8/8, jail1 1/8 и6/8, ware2 2/8 и8/8. Пары являются более перспективным учебным набором по исполнимости rules; это не чистый парный эксперимент удаления третьего монстра, поскольку у прежних троек были отдельные сиды.

Первый нативный урон после отпускания: parent в21 случаях из32, среднее61,43 native-frame =6,143с, максимум193frame;11 случаев без урона. Rules в30/32, задержка15frame =1,5с; два случая без урона. Это время в мире игры при ×2, не wall-time. Среднее условно по случаям с уроном; это не время первого выстрела. Урон независимо сверяется с first-life total.

Новый correct-clock audit модели:5168 provider-кадров,3997 предложений атаки,1904 подавленных атак,1124 полностью подавленных команд движения. Прежний оружейный audit с историческим порогом:99 запросов,35 на уже экипированное оружие,2560 кадров вне поддерживаемого набора огня,максимальная непрерывная серия keep с видимым врагом171кадр. Их показатели используют разные пороги и не должны арифметически смешиваться. Наблюдаемые переходы доступны в `weapon-parent.json`, ограничения исполнения —в `execution-parent.json`.

Решение: брать пары как ранний этап recovery curriculum, сохранять обычные бои для проверки регрессий. Следующая отдельная ветка должна повысить исследование именно weapon-head, не одновременно увеличивать случайность прицела и движения. Сначала CUDA-проверка вероятностей/логитов и сохранности прочих выходов, затем собственный свежий train-пул; более высокая общая entropy без разделения голов пока не принимается как решение. Новых весов этот диагностический этап не создаёт.
