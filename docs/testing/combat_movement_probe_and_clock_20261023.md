# Манёвры: рабочий диагностический контракт и исправленный clock

23 октября 2026. Обучения новой модели не было. Geometry8 не показала независимого превосходства над правилами; вместо дальнейшей оценки тех же весов начат сбор реальных последствий манёвров.

## Реализованный контракт

`diagnostic_movement_probe`, version `combat_one_frame_movement_mean_shift_v1`: один кадр, два сдвига среднего Gaussian движения, каждый в[-2,2]. Std и порядок всех случайных выборок прежние. Связанная с sampled movement доводка и conditional fire пересчитываются штатно. Это не подмена готовой команды.

Native Review и CUDA учитывают сдвиг в полной совместной вероятности. Вне кадра обычная политика; zero shift — точный контроль. До игр CUDA проверила неизменность NN state, совпадение акторных выходов, точность контроля и аналитическую разность Gaussian log_probability. Внутри диагностического кадра записаны четыре исходных Gaussian noise и fire uniform. Обычные PPO, merged rollout processing и quality evaluation отвергают диагностические модели/данные.

Чистые Go metadata/scalar тесты и сборки прошли без NN forward. Обучение и численные NN-проверки толькоCUDA; native NN только в реальных играх.

## Первый отказ приёмки сохранён

Первая серия6native/6CUDA прошла технические проверки, но полный zero-shift контроль не воспроизвёл исходную обычную траекторию. Все6результатов тогда исключены из меток.

В кадре144 source baseline имел timing[0]=0,03, то есть9мс возраста наблюдения; zero-shift повтор —0. Исходный Gaussian draw совпал, но logits головы углов изменились и framehash выбрал category13 вместо12, изменилась pitch-команда. Это реальное расхождение действия, а не несущественная разница округления.

В синхронном харнесе сервер удерживает мир между наблюдением и следующим native command. Время вычисления в стеночных часах не является временем движения мира. В `combatObservationAge` для released synchronous mode используется physical age0; отрицательный возраст и>300мс сохраняются для прежнего stale guard. Обычный realtime/coop режим сохраняет прежнюю обработку wall age.

Manifest и exported metadata теперь содержат `observation_timing_contract=frozen_world_v1`; legacy captures обозначаются отдельно, merge не смешивает контракты. PPO exporter проверяет нулевой physical age всех provider observations нового контракта. Старые captures/пороги/оценки не переписаны. Новая семантика входа требует новой оценки любого будущего обученного кандидата; старые результаты не являются оценкой новой среды.

## Живая приёмка после исправления

Серия7native/7CUDA: шесть вариантов плюс отдельный обычный source без диагностического header. Полный zero-shift бой воспроизвёл этот свежий обычный reference. Все6вариантов имеют одинаковые состояния/префиксы до вмешательства, точные Gaussian noise/fire draws, прежние target/aimmode/vertical/weapon. Сдвиг movement latent подтверждён. Правила до окончания задачи не управляли; три rules commands у выигранных случаев относятся к cleanup после последнего убийства.

Один TRAIN контекст: base3, seed1164065132, frame108. Бот движется около100units/s и целится вgunner, parasite виден на расстоянии144,5. В группе такжеinfantry. Выбор сделан по наблюдаемым условиям, не по будущим альтернативным исходам и не изconfirmation.

После единственного вмешательства работает прежняя политика. Прицел/огонь могут ответить на новое sampled movement; это предусмотренная связка, а не доказательство эффекта движения при искусственно замороженном прицеле. Сохранившаяся победа при меньшем уроне относится к одному условному продолжению, не к ожидаемомуQ и не к универсальному правилу «всегда влево».

Актуальная приёмка `combat-movement-probe-proof-v3-20261023`:6admitted/0excluded. Исходные неуспешные `smoke-v1`/`proof-v1` сохранены; актуальные native captures `smoke-v2`, свежий обычный reference включён. Базовая CUDA preparation `combat-movement-probe-preparation-v1-20261023` выбрала26доступных наблюдаемых контекстов из прежних32TRAIN, но дальнейший сбор использует новые baseline с исправленным clock.
