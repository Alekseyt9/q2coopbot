# Учебная точка прицеливания: верх корпуса против центра bbox

Статус: подготовлены одинаковые учебные примеры, завершены CUDA пары80 и200 steps. Smoke24 native/16 CUDA закрыт с положительным малым сигналом; начат screen72 native/48 CUDA. Общее превосходство и устранение лишних действий не установлены.

## Зачем проверять

[Native аудит](combat_native_ballistic_geometry_20261021.md) показал запас геометрических пересечений bbox при смещении идеального направления от верхней точки к центру. Это наблюдение по оценочным боям служит гипотезой; сами эти бои в обучение не включаются. Верхняя точка22 units с ограничением внутри bbox оставляет небольшой запас до его верхнего края при MG spread.

В новом опыте используется только исходный закрытый train/development corpus и его исправленный release export `combat-sampled-motion-labels-release-v2-20261021`. Центр считается по реальным native mins/maxs/origin в момент выстрела, с фактическим muzzle и fresh recoil как offline labels. Эти данные не становятся скрытыми входами рабочего агента.

Центр не проверен на видимость: BSP, укрытие или другой противник могут закрыть его при видимой верхней части корпуса. Это экспериментальный геометрический teacher, не оптимальный контроллер. Не отменяется случайный spread и не меняется native физика. Решение принимается по новым настоящим боям.

## Одинаковые примеры в обеих ветках

`scripts/prepare_combat_bodypoint_labels.py` создаёт верхние и центральные метки с одинаковыми seed/index/features/sample. Оставляет только строки, где обе команды достижимы уже выбранным coarse/fine режимом и нет water/muzzle-blocked. Это исключает смешение эффекта точки с разницей пригодных учебных кадров.

| Split | Исходных меток | Общих пригодных | Исключено | Только upper пригодна | Только center пригодна |
|---|---:|---:|---:|---:|---:|
| Train |1239|1095|144|46|14|
| Development |641|557|84|25|6|

Среднее абсолютное изменение pitch метки4.885° train/4.828° development. На одной и той же выборке меняется только желаемая точка, исходные признаки и действия остаются прежними. Gzip потоки детерминированы; script/source/report/stream SHA закреплены. Исходные экспорты не переписаны. Наблюдаемая клиентская ошибка для center отсутствует, прежняя upper diagnostic отдельно названа, чтобы не выдавать её за новую метрику.

Три новых geometry/common-support теста пройдены без NN исполнения. Численные проверки сетей и fit выполняются только CUDA.

## Первый фиксированный пилот

`combat-bodypoint-ab-v1-20261021/protocol.json` закреплён до обучения. Обе ветки исходят из `combat-vertical-aim-control-zero-v1-20261021`:128→64→32→2,10402 параметра, selected-vertical каналы отключены. Это одинаковая архитектура, не продолжение проигравшего vertical candidate. Меняется только обучение conditional aim; остальные actor/value/log_std заморожены. Пара80 steps,lr0.0003,retention0.02,seed20261022, без выбора checkpoint по development.

Checkpoints: `combat-bodypoint-upper-bc-v1-20261021`, `combat-bodypoint-center-bc-v1-20261021`. CUDA audit подтвердил общий начальный checkpoint, одни retention histories, неизменность остальных параметров и одинаковый raw actor. Ошибки на557 development примерах:

|---|---:|---:|
| Upper |4.068|4.608|

Ошибки сравнимы внутри столбца, не по диагонали. Среднее подписанное изменение pitch action всего+0.318°, среднее абсолютное по оси0.217°, максимум2.656°. Это не боевой выигрыш. Учебная точка меняется заметно сильнее, чем выученное среднее.

## Вторая фиксированная пара: проверить достаточность обучения

До новых fits сохранён `combat-bodypoint-calibrated-ab-v1-20261021/protocol.json`:200 steps/ветку,retention0.002, прежние lr/seed/исходные веса/1095+557 примеров. Обе ветки получают одинаковый новый бюджет. Development был просмотрен при пересмотре протокола; это разработческий, не финальный holdout. Выбор лучшего промежуточного checkpoint не выполняется.

Основание для проверки: текущий latent aim std≈0.0202, то есть fine шум около0.303° при малом угле. KL удержания может сильно ограничивать сдвиг на несколько градусов. Это гипотеза о недостаточном перенятии новой метки; увеличение бюджета и уменьшение penalty меняются одновременно для обеих веток, поэтому сравнение со старым пилотом не устанавливает отдельный эффект этих двух факторов.

После завершения — CUDA cross-teacher audit и свежий matched smoke8 условий/вариант, верхняя/центральная модель/правила через существующий пул16 ×2. Старые результаты vertical screen не подменяют контроль для новой пары. Promotion исключён; сохранять primary исходы, урон, настоящие попадания/расход и признаки лишних действий. Пока нет закрытого native сравнения, center teacher не считается улучшением.

Оба selected-vertical входа отключены. `training-complete.json` закрывает только учебную фазу; promotion=false.
