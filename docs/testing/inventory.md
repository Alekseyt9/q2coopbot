# Инвентарь UDP-клиента

Клиент разбирает `svc_inventory` (256 знаковых 16-битных количеств), имена получает из `CS_ITEMS`. Ненулевые слоты публикуются как `inventory: [{id,name,count}]` в world snapshot и JSONL. Слот без известного имени сохраняется по ID; нулевое количество удаляет предмет из списка. `inventory_known=false` означает отсутствие данных, а не пустой инвентарь. `inventory_age_frames` показывает возраст последнего полного сообщения. Новая серверная сессия очищает данные. Перед первым открытием инвентаря выдерживаются три игровых кадра, чтобы начальные configstrings/precaches не накладывались на поток инвентаря.

Обычный бот открывает свой инвентарь командой `inven`; используемый Yamagi обновляет его каждый серверный кадр (`game/player/view.c`). Бит инвентаря в `STAT_LAYOUTS` предотвращает повторное переключение окна; при закрытии запрос повторяется не чаще раза в 20 кадров. У тестового актора в режиме idle запросы отключены. Сообщение с неполными 256 слотами отвергается целиком.

При двух кадрах с пустым боезапасом бот выбирает доступное оружие из свежего инвентаря, учитывая расход на выстрел; при отсутствии подходящего оружия использует Blaster. При неизвестном/устаревшем инвентаре делегирует выбор серверу через `weapnext`. Повторы ограничены тремя запросами с интервалом 20 кадров, запасные запросы выбирают Blaster. Подтверждение — новое активное оружие и боезапас в последующих серверных кадрах, а не отправка команды. После получения патронов, смерти или новой сессии состояние попыток сбрасывается. Политика предназначена для baseq2; это ещё не выбор оружия по тактической эффективности и не автоматический подбор предметов на карте.

Трасса дополнена `weapon`, `ammo`, `armor`, `weapon_request`. Имена команд выбора оружия берутся из локального списка, а не исполняются из серверных строк.

Проверка: `./scripts/run_weapon_switch_trial.ps1 -Timescales 2,1`. Два варианта на base1: Shotgun с одним патроном и только Blaster в запасе; Shotgun с одним патроном и Machinegun с 20 патронами. Харнес выдаёт начальный инвентарь только в тестовом режиме, а расход патрона, выбор оружия и дальнейший огонь выполняет обычный клиент. Критерии требуют выстрел последним патроном, обновление инвентаря до нуля, адресный запрос выбора, смену оружия и возобновление огня. Проверки применённых сервером команд и пропусков кадров остаются обязательными.

Принято 4/4: `workspace/artifacts/weapon-switch-20260926-200912/report.json`, оба варианта на 2×/1×, ноль пропущенных кадров и ошибок декодирования. В stocked/1× после Machinegun дополнительно выбран Blaster при исчерпании его патронов. `go test ./...` прошёл. Предыдущие отказы подготовки и прогоны с потерей кадра сохранены; финальный отчёт их не подменяет. Реестр поддерживает `kind: weapon_switch`, у которого `scenario` указывает на скрипт этого парного теста. Историческая сцена bunk1 не восстановлена целиком; принята функциональная регрессия автоматического переключения. Подбор оружия, патронов и брони с земли остаётся отдельной задачей.

Серверная поправка Yamagi (2026-09-26): `Cmd_Inven_f` больше не дублирует немедленным надёжным сообщением инвентарь, который уже отправляет `ClientEndServerFrame` каждый тик. Две копии по 513 байт при открытии вытесняли игровой snapshot из ограниченного сетевого пакета на base3 (`Netchan_Transmit: dumped unreliable`). Go-протокол не менялся; требуется новая тестовая `game.dll` для устранения этого серверного переполнения. Исходная живая игровая сессия не обновлялась.
