# Очистка диска и исправление накопления runtime — 2026-10-06

Обучение приостановлено для обслуживания диска по запросу пользователя. Четыре
обновления narrow-aim PPO закончены, финальная парная оценка была прервана.
Checkpoint `workspace/artifacts/combat-ppo-narrow-aim-mixed-v4-20261006/iteration-4/update/checkpoint.pt`
и веса сохранены; завершённой оценки боевого качества здесь нет.

## Причина

Для каждого эпизода создавался отдельный runtime. PAK сначала подключались
жёсткими ссылками, но после достижения ограничения NTFS в 1024 ссылки на один
файл скрипт переходил к полной копии. Это добавляло около 197 МБ на эпизод.
Кроме того, тысячи копий EXE, DLL и AAS оставались после прогонов.

До очистки сумма размеров файлов во всём `F:\src\quake2` была 598,88 ГБ.
Она завышала физический расход из-за существовавших жёстких ссылок: сумма
длин уникальных файлов составляла 316,04 ГБ. Все числа здесь в десятичных ГБ.

## Что сделано

- Удалены 7623 PAK-пути только внутри `workspace/artifacts`: размер и полный
  SHA256 совпадали с каноническими `F:\src\quake2\assets\baseq2\pak*.pak`.
  Освободилось 246,11 ГБ. Канонические ресурсы и пользовательский runtime
  вне artifacts сохранены.
- 11669 одинаковых EXE/DLL/AAS/BSP заменены жёсткими ссылками после полного
  сравнения SHA256. Все исторические пути и содержимое сохранены. Лимит
  числа ссылок учитывается; разные сборки не объединяются.
- Для JSONL, JSON, LOG, SAV и PT включено обычное NTFS-сжатие. Оно прозрачно
  для чтения и не меняет содержимое или SHA256. Отчёт compact: 21,36 ГБ
  данных хранятся в 11,56 ГБ; исходные трассы и checkpoints сохранены.
- Остались модели, награды, отчёты, исходные логи и данные для проверки обучения.
  Пользовательские сохранения, конфигурация и исходники не удалялись.

После операций контрольный замер дал:

| Область | Сумма размеров всех путей | Уникальные данные | Место на диске |
|---|---:|---:|---:|
| `workspace/artifacts` | 80,28 ГБ | 30,82 ГБ | 21,12 ГБ |
| Весь `F:\src\quake2` | 99,78 ГБ | 44,91 ГБ | 35,64 ГБ |

Свободно на F: 296,21 ГБ против 15,20 ГБ перед удалением PAK.
Замер включает последующие короткие проверки.
«Место на диске» посчитано через Windows GetCompressedFileSizeW, с округлением
до 4096 байт и учётом каждого file ID один раз; метаданные NTFS не включены.
Общие файлы между папками нельзя суммировать повторно. Проводник может показывать
около 80 ГБ, суммируя логические размеры всех путей к общим данным.

## Защита новых прогонов

`scripts/prepare_runtime.ps1` использует кеш неизменяемых снимков по SHA256
для EXE, DLL и AAS. Снимок не связан с изменяемым выходом сборки. Обновление
runtime заменяет запись файла атомарно и не перезаписывает данные общей ссылки.
Кратковременная блокировка при параллельном хешировании допускает ограниченный
повтор замены. При переполнении ссылок PAK создаётся очередной общий shard,
вместо индивидуальных копий на каждый эпизод. Для разных дисков применяется копия.

Подготовщики специальных AAS-фикстур также заменяют запись через общий helper,
чтобы не изменять кеш и другие runtime. Изменяемые ENT остаются отдельными файлами.

`scripts/run_learned_combat_baseline.ps1` после окончания capture/export по
умолчанию удаляет PAK-ссылки в принадлежащих харнесу runtime внутри artifacts.
`-KeepRuntimeAssets` сохраняет их для отладки. Cleanup проверяет границы,
reparse points, marker, отсутствие процессов runtime и SHA256 всех PAK до
удаления первого файла; остальные файлы сохраняются.

## Проверки и ограничения

- `test_prepare_runtime_paks.ps1`: прямые ссылки, переполнение исходника и
  shard, повреждённый кеш, отсутствие временных файлов; общий снимок,
  изоляция от новой сборки и от замены другого runtime.
- `test_prepare_runtime.ps1`: явная замена AAS, сохранение старой live-ссылки,
  отсутствие неявного отката AAS.
- `test_cleanup_completed_runtime_paks.ps1`: сохранение ресурсов и логов,
  идемпотентность, отказ при повреждении, отсутствии marker, выходе за границы
  и junction. PowerShell parsing и `git diff --check` проходят.
- Реальные capture: 4 native сервера/UDP-клиента, x2, независимые seeds
  18404–18407, Mixed, 150 кадров. После удаления PAK проверка `q2ppo-data`
  подтвердила 529 переходов, один terminal в `harness-shared-mixed-rollout`.
  Финальная проверка после всех правок — `harness-shared-complete`, все 4
  capture валидны; экспорт `harness-shared-complete-rollout` подтвердил 447
  переходов, два terminal. Более ранняя проверка удаления PAK подтвердила
  471 переход. Это отдельные диагностические capture, не тренировочные batches.
- Неполные диагностические запуски сохранены и исключены из обучения:
  слишком короткий budget, повреждение кеша старым overwrite до его исправления,
  блокировка до добавления retry, а также solo-прогоны, не прошедшие критерий
  движения старой фикстуры. Они не подтверждают боевое улучшение.
- Go/native боевой код не менялся. Эти проверки подтверждают хранение и
  работоспособность захвата/экспорта; полной эквивалентности reset мира или
  завершённой оценки narrow-aim PPO они не доказывают.

Игнорируемые подробные инвентаризации, SHA256 и receipts находятся в
`workspace/artifacts/storage-maintenance-20261006/`: `storage-before.json`,
`storage-after.json`, `artifact-inventory.json`, `pak-cleanup-receipt.json`,
`immutable-dedup-receipt.json`, `compression.log`, `storage-final.json`.
