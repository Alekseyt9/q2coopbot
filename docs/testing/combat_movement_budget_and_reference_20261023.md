## Четыре против восьми продолжений

Завершён заранее заданный `../combat_movement_mc_budget8_protocol_20261023.json`:112 новых native/112CUDA, один пул до16инстансов,×2. Добавлены четыре последующих policy RNG потока к прежним четырём для тех же четырёх TRAIN состояний. Старые85захватов не переписывались и не повторялись. Все28старых/новых fork units приняты; отдельный supplement о пустом post-goal хвосте сохраняет первоначальный отказ полного совпадения одной старой записи.

Лучшие множества действий по средним первых четырёх и новых четырёх продолжений пересекаются в3/4сценах. Но заметный положительный эффект выбранного по первой половине ненулевого манёвра (delta≥0,25) повторился только в1сцене при требовании≥2. Худшая новая средняя разница выбранного действия−0,015 не нарушает предел−0,25. Поэтому техническая приёмка данных прошла, а `budget4_supported=false`. Нет допуска к обучению.

Это не доказательство бесполезности усреднения: средние устойчивее отдельных исходов. Однако восьмисэмпловые средние не получили независимого подтверждения. Все root draws кадра вмешательства фиксированы; меняется только дальнейшая случайность. Полученные оценки относятся к фактическому sampled root action, а не к распределению mean-shift до Gaussian draw. Для нового teacher нужны фактические предложенные действия во входах либо отдельное усреднение root draws. Четыре мира недостаточны для проверки общей боевой политики.

Артефакт: `workspace/artifacts/combat-movement-mc-budget8-v1-20261023/dataset/report.json`.

## Неявная связь изменения среднего движения и прицела

Закрыт CUDA-only audit `combat-movement-reference-coupling-v1-20261023`. По одному минимальному TRAIN сиду на каждой из четырёх карт проверены изменения raw movement bias±0,02по каждой координате. История наблюдений, sampled actions и остальные веса фиксированы. Изменение raw movement reference действительно меняет условный прицел. Отношение среднего conditional aim Gaussian KL к movement KL на167eligibleстроках составляет1,24/1,22для первой координаты и4,45/4,53для второй.

Предварительный критерий материальности требовал отношения≥5как минимум для3из4поправок. Ни одна не достигла5, поэтому `material_coupling=false`. Это локальная проверка, не полный joint KL и не доказательство причины прошлых PPO отказов. Внешняя additive movement-mean поправка сохраняет условный прицел при фиксированном sampled movement; в реальной игре изменённое движение по-прежнему должно менять условный прицел. Не объявляем разъединение heads доказанным лечением.

## Следующий опыт: несколько кадров движения

Перед большим новым teacher проверяется пятикадровая поправка движения, примерно0,5игровой секунды, по `../combat_movement_window_smoke_protocol_20261023.json`. Версионированный диагностический контракт сохраняет rawactor/std/RNG порядок; прицел, fire, target и weapon вычисляет прежняя сеть. В каждом затронутом кадре записываются фактический frame, Gaussian noises и fire uniform. Обычное PPO не принимает эти данные. Однокадровый контракт сохраняет прежнее поведение.

Шесть smoke игр включают нулевой пятикадровый контроль, left1, left5, right5, backward5 и свежий ordinary reference. Все6native/6CUDA завершены;5/5вмешательств приняты, полный нулевой контроль совпал с ordinary reference. Для каждого пятикадрового случая приняты5receipt с общимиGaussian/fire draws. CUDA reconstruction maxerror≤1,44e−6. До конца задачи правила не вмешивались.

| Вариант одной TRAIN сцены | Цель | Убийства | Получено |

| Left1 |нет, смерть|1|80|

Таким образом, длительность меняет последствия; Left5 здесь не лучше control по полученному урону. Это одна сцена с одним потоком, не преимущество длинных манёвров. Артефакты `combat-movement-window-{preparation,smoke,proof}-v1-20261023`.

Дополнительная техническая проверка перекрывающихся window и continuation RNG fork завершена4native/4CUDA по `../combat_movement_window_continuation_smoke_protocol_20261023.json`. Полное совпадение forked zero/reference и old ordinary/no-fork, точный prefix/root и общие draws всего продолжения подтверждены. В обоих вмешательствах приняты5window receipts, правильные CUDA Gaussian/fire reconstruction включая перекрытие с fork сF+1. Control здесь погиб с0убийств, left5погиб с1убийством; это другой future stream. Артефакты `combat-movement-window-continuation-{preparation,smoke,proof}-v1-20261023`.

После этой приёмки зафиксирован `../combat_movement_window_comparison_protocol_20261023.json`:4TRAIN мира×4старых общих future streams, control/left/right/forward/backward на5кадров, fork-only refs и один no-fork replay на мир. Новых100native/100CUDA, подготовлены16единиц с неизменными NNпараметрами. Старые однокадровые captures для техже потоков1..4используются без переигрывания; near_stationary не входит, чтобы сравнивались одинаковые четыре направления. Перед сравнением вмешательств обязательна дополнительная физическая/command/feature проверка zero-control между старым и новым сбором до конца задачи, кроме уже явно принятого пустого post-goal хвоста.

Signal screen задан до игр: выбранное по первым двум продолжениям ненулевое длинное действие должно дать≥0,25на новых двух как минимум в2мирах; худший new-half gain≥−0,25; средний long-minus-short того же выбранного направления≥0,25как минимум в2мирах. Это предварительный TRAIN screen длительности, не отмена прежнего отрицательного результата о достаточности четырёх повторов. Даже его успех не допускает fitting на этих четырёх состояниях: дальше нужен новый независимый teacher с явным root-action conditioning и отдельным бюджетом повторов. На момент записи22:39сбор запущен, результата сигнала ещё нет.
