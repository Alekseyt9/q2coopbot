# Видимые динамические тела в наблюдении боя

24.10.2026. Передача данных реализована и проверена в игре. Подключение к входам сети и обучение ещё не выполнены; преимущество в бою не заявляется.

## Основание

Разбор 192 TRAIN боёв нашёл 260 реальных попаданий автомата в труп. Во всех 260 соответствующий ID уже был в клиентском `Defeated` до команды; в 227 он также присутствовал в `CollisionBodies` с ненулевым protocol solid. В текущих enemies/props/remembered threats модели его не было ни в одном случае. Во всех случаях труп отличался от выбранной цели.

Геометрический разбор отдельно нашёл 197 попаданий в труп на пути к хитбоксу выбранного живого монстра. Это объясняет, почему команда с выбранной видимой целью всё же может задевать труп; не доказывает, что новый вход сам по себе улучшит исходы. Большинство других ошибок связано с лучом, проходящим мимо выбранного bbox. Простого исправления только тел недостаточно для всей цели проекта.

Источники: `combat-execution-contract-body-visibility-v1-20261024` и `combat-execution-contract-train-geometry-v1-20261024`; подробности в `combat_execution_contract_train_geometry_20261024.md`.

## Реализация

- `quake.Decoder` сохраняет в CollisionBodies/Defeated уже доступные поля сетевой сущности: model, animation frame, skin, angles и protocol solid. Здоровье и native bbox не добавляются.
- Optional поле `Observation.DynamicBodies` имеет собственную версию `observed_dynamic_bodies_v1`. Набор объединяет текущие CollisionBodies и Defeated, исключает себя, ограничен 512 units и 16 объектами, сортируется по расстоянию и ID, сообщает truncation.
- Объект проходит текущую статическую BSP/observed-door visibility проверку. Наличие в PVS не является достаточным. Это проверка до команды; точная видимость из будущей позиции ствола не утверждается.
- Поле содержит относительное положение, наблюдаемую модель/класс/анимацию/ориентацию, protocol solid, маску `protocol_bounds_known` и границы только при доступном корректном encoded hull. Известный `solid=0` не означает, что пуля пройдёт сквозь труп; server damage hitbox не подставляется.
- Nil набор означает недоступность, present empty — отсутствие подходящих видимых тел. `observed_death_animation` описывает клиентскую классификацию анимации, не скрытое server health и не вечную метку entity ID.

Код: `internal/policy/dynamic_bodies.go`, `contract.go`, `environment.go`; сохранение packet appearance — `internal/quake/decode.go`. Исполнитель боевых действий не менялся: нет нового запрета огня, автоприцела или принудительного обхода.

## Проверки

Прошли целевые Go tests только метаданных/наблюдения/геометрии: видимость через actual base1 BSP, фильтрация скрытых и дальних объектов, исключение self, stable ordering/cap, nil/empty masks, неизвестная форма тела, отсутствие alias с исходным snapshot, packet appearance и классификация смерти/возрождения. Go NN-тесты не запускались.

`combat-dynamic-bodies-smoke-v1-20261024`: четыре свежие TRAIN сцены с тремя противниками на base3/city1/jail1/ware2, существующий пул до16, ×2. Каждый случай имеет свой новый seed, проверено отсутствие пересечения с историей. Native 4/4 usable, source_unchanged=true; CUDA 4/4, 501 принятый переход. Fitting отсутствует. ## Следующий этап и ограничения

Нужен отдельный версионированный neural input/context и CUDA перенос, сохраняющий исходное поведение до обучения. Нельзя назвать v10 веса body-aware, просто добавив JSON поле, или смешать старые записи без новых масок с новым корпусом. Если подключение затрагивает scorer/checkpoint/optimizer, оно получает явный scope и проверяемое продолжение обучения.

После этого — собственные свежие on-policy бои с новым входом и равнобюджетный контроль. Качество проверяется отдельными сценами против исходной модели и rules: цели, смерти/урон, реальные impacts, стояние/повороты. Старые geometry/visibility labels остаются разбором/возможными TRAIN метками; они не становятся скрытыми runtime признаками. До успешной оценки default и опубликованные веса не продвигаются.
