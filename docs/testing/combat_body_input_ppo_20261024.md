# Подключение динамических тел к сети

24.10.2026. Формат, CUDA перенос и игровая проверка нулевой инициализации завершены. Полноценного обучения этого входа и оценки его боевой пользы ещё нет.

## Формат

`combat_features_v11` сохраняет весь v10 префикс из 1147 признаков и добавляет 322 признака: availability/truncation и 16 слотов по 20 значений. Итого 1469. Слот содержит относительную позицию в системе взгляда, дистанцию, маску и доступные protocol bounds, наблюдаемую death animation, общие признаки модели, yaw и номер анимации. Entity IDs, server health и native bbox в вектор не входят. `solid=0` не получает выдуманную форму.

Контроль `combat_features_v11_body_ablated` имеет ту же ширину, но весь новый хвост равен нулю; исходное наблюдение при этом валидируется. Старые версии признаков сохраняют прежний смысл. Вспомогательные головы, обученные на v10, читают прежний префикс; новые каналы поступают в основной encoder actor/value перед существующим Temporal Attention с окном32.

В actor и value первая скрытая ширина64. Расширение добавляет по20608 входных весов, суммарно41216, без добавления новых слоёв. Новые колонки в начальных JSON/CP равны нулю. Код: `internal/policy/body_features.go`, `scripts/combat_body_features.py`, совместимость существующих голов/loader.

## Игровая проверка и исправления

Parity — четыре заранее заданные сцены base3/city1/jail1/ware2 с тремя противниками, source-v10 / body-initial / body-ablated-initial. Всего12 native/12 CUDA, pool≤16, ×2; fitting отсутствует.

1. `combat-body-input-parity-v1-20261024` остановился до создания pool: внутренний geometry predictor metadata validator разрешал толькоv10. Расширена совместимость с прежним префиксом; source веса не менялись. Не было игр или обучения.
2. `...parity-v2...` закрыл12 native/12 CUDA, но source дал446 rows, две новые версии449. Сравнение реальных кадров нашло причину: новый номер версии не входил в runtime условие длинной памяти угроз. На jail1 после потери видимости новые модели отдали12 кадров правилам, source продолжал бой. До этого команды/мир совпадали; это реальный control ownership bug, не float-погрешность. Все записи сохранены.
3. Добавлена capability `PPO.UsesThreatMemory()`, и bot выбирает grace по ней. Пройдены metadata tests новых headers/версий и обычные engagement tests без Go NN исполнения. `...parity-v3...` повторил те же известные технические сцены после исправления с теми же весами. Это повтор для проверки механизма, не свежий quality holdout.

Финальный `combat-body-input-parity-audit-v1-20261024`, report SHA `d1f3dd40331962850c1af8221a5ec491384e6621c566fb36f763d4c4a3bfea91`, gate=true:

- 12 native/12 CUDA, по446 rows на версию, суммарно1338.
- 8/8 сравнений новых версий с source: одинаковые frame sets, фактически отправленные команды, ownership и наблюдаемые состояния мира до цели/смерти; shutdown tail исключён.
- v10 prefix совпал; записанный Go хвост совпал с CUDA кодировщиком (max error0 в float32).
- Исходы одинаковы:2/4 цели,2 смерти,9 kills,309 HP получено. Это приёмка переноса на четырёх повторённых мирах, не преимущество в бою и не12 независимых условий.

## Перед полноценным обучением

Реализовать отдельный trainer и зафиксировать его scope/evaluation spec до fit. Плановый бюджет — четыре раунда по24 собственных TRAIN боя на ветку,192 суммарно, последняя версия после четвёртого раунда; промежуточные checkpoint по quality не выбирать. Fitting и NN проверки только CUDA, один shared pool≤16 ×2, внешняя история использованных сидов.

Нужно убрать возможное смешение эффекта тела с дополнительной свободой encoder bias: availability-колонка у observed может работать как новый bias, тогда как весь хвост ablated нулевой. В финальном scope обеим веткам следует одинаково разрешить обучение общего input bias (новая одинаковая Adam группа), сохранив исходную сеть и начальную нулевую поправку. Это изменение optimizer layout требует нового явно версионированного training scope/protocol, а не молчаливого изменения закрытых initializer-v1 receipts. Параметры сети и исходные команды менять для этого не требуется.

После scope/первого реального update проверить checkpoint/Adam продолжение, фактическое изменение body колонок и корректный CUDA/native replay уже ненулевой сети. Затем завершить парный бюджет и оценить initial/final обеих веток плюс rules на новых условиях. Корпуса не смешивать между feature versions; просмотренные parity сцены и старые validation записи не подавать в fit. Тела — только одна из найденных проблем, основная цель эффективного полного боя и превосходства над rules остаётся открытой.
