## Общий реестр

Компактный вход: `scripts/scenarios/combat-teachers/continuations.json`. Корпус и manifest: `workspace/artifacts/combat-continuation-evidence-v1-20261026/`. Первоначальный single-pair индекс `combat-teachers/index.json` не изменён; старые эксперименты остаются воспроизводимыми.

Объединены все четыре завершённых результата без выбора удобных состояний: **20 состояний, 20 миров, 17 карт, 92 уникальных парных продолжения**. Это 276 native/CUDA ветвей с baseline controls; повторно используемые original streams удалены как дубликаты, а не посчитаны новыми попытками. В восьми состояниях по семь продолжений, в двенадцати — по три. Все 72 запрошенных fork streams наблюдались в обеих ветвях.

- В 14 состояниях все пары автономны; в шести есть mixed control.
- 11 пар из 92 имеют active rules control и сохранены с отметкой.
- В 11/20 состояний наблюдались оба знака автономного предпочтения. Это не означает равенства ожидаемых ценностей действий.
- Сами 20 record-файлов занимают около 492 КБ; telemetry и веса в них не дублируются.

`build_combat_continuation_evidence.py` требует complete receipts всех источников, связывает результаты/модели/rollout/CUDA proofs через SHA, проверяет неизменность core source model, root features/source latent, одинаковый fork seed пары и соответствие return исходным записям. Разные reward/execution contracts не смешиваются. Первоначальный двухконтекстный pilot не имел нового поля historical_root_exact; реальные root features/latent проверяются заново для обеих ветвей каждого продолжения.

`combat_continuation_evidence.py` отделяет causal input от будущих результатов. Входной whitelist и значения взяты из первоначального source teacher: features, source latent, pre-gate context187 и доступные параметры выбора. Future utility, goal/death, RNG stream и ownership находятся только в evidence. Сохранены версия награды, её SHA, discount и execution contract. Для каждого stream отдельно отмечено фактическое наблюдение fork; простой повтор завершившегося до fork боя не выдаётся за новую случайность.

Среднее и sample stddev вычисляются только когда **все** сохранённые пары состояния автономны. Отфильтрованное среднее по «удачным» чистым продолжениям смешанного состояния не выпускается. Частоты choice0/tie/choice1 описывают наблюдения с порогом .05, не являются бинарными train targets. `ordinary_ppo_eligible=false`, `training_target_emitted=false`. Критическая единица будущего разделения — карта; число streams не должно увеличивать вес одного мира относительно других.

Metadata regressions проверили запрет future-поля во входе, duplicate stream, изменение summary, неверный ordinary-PPO статус, сохранение hybrid без filtered mean и отказ при изменении corpus-файла. Загрузка компактного индекса повторно приняла все 20 состояний.

## Следующий шаг

Проверить на GPU, можно ли предсказывать **среднюю величину преимущества**, а не бинарного победителя одной пары: сравнить простой постоянный прогноз с контекстным на разделении по картам. Это небольшой исследовательский probe с явным учётом 3/7 продолжений и только 14 полностью автономных состояний. Он не даёт основания экспортировать новый actor или объявлять качество лучше правил без отдельной native оценки.
