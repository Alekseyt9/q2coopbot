# Реестр эпизодов

`episodes.json` — единый список наблюдаемых ошибок, включая ещё не воспроизводимые. Сценарии лежат в `scripts/scenarios`, исходные трассы и результаты — в игнорируемой `workspace/artifacts`. Без сохранённых локальных артефактов историческую трассу нельзя восстановить из Git; JSON-сценарии доступны из репозитория.

Каждая запись содержит ID, карту, симптомы, статус исправления, готовность воспроизведения, сценарий, исходное свидетельство, недостающую подготовку и критерий приёмки. `observation_only` никогда автоматически не считается проходящим тестом. `ready` означает готовность запустить воспроизведение, а не исправленность ошибки.

Команды из корня проекта:

```powershell
./scripts/run_episode_regressions.ps1 -List
./scripts/run_episode_regressions.ps1 -Id base2-bridge
./scripts/run_episode_regressions.ps1 -Id base1-stairs,base2-bridge -Timescales 1,2
```

Runner собирает текущего бота один раз, запускает существующий UDP-харнес последовательно на отдельном тестовом порту, сохраняет копию реестра и `report.json`. Текущая человеческая сессия не используется. Для приёмки проверяются серверные команды через штатный runner, затем фактическая позиция живого бота на земле, требуемое событие и возобновление движения. Успешного старта сервера либо выбора цели недостаточно. Ненулевой результат блокирует E2E-приёмку. Это пока не детерминированное восстановление полной сохранённой игры и не замена suite/provenance-манифестам.

При новой ошибке сначала сохраняем трассу, добавляем `observation_only`, перечисляем недостающие условия. После появления точного сценария и исполняемого критерия переводим в `ready`. Статус исправления меняем только по проверенным результатам; runner сам реестр не переписывает.

## 2026-09-26: выход с поднятой платформы bunk1

Диагностика `bunk1-stuck-20260926-194231` выявила отдельную ошибку: бот на верхней поверхности func_plat *100 (`self.z=232.125`) получает статический AAS-маршрут с первой точкой на нижнем полу (`z=24`). Он подходит по XY и останавливается с `at_waypoint`. Обычное обновление маршрута сохраняет ошибку, потому что AAS не описывает текущую опору на поднятой платформе.

Добавлен `internal/bot/platform_exit.go`: при таком несовпадении бот ищет соседний статический пол на той же высоте. Необходимы видимый mover func_plat непосредственно под ногами, on_ground, свободный проход для корпуса, отсутствие блокирующих дверей, безопасная область назначения и продолжение AAS-маршрута от неё. Проверяется опора вдоль перехода; маленький стык платформы и пола допускается при сохранении минимум 8 единиц перекрытия корпуса с платформой. Исполнитель не прыгает, пересчитывает маршрут по мере выхода и не заменяет активное управление лифтом или команды hold/attack.

Контрольный эпизод `bunk1-raised-platform-exit` / `scripts/scenarios/bunk1-platform-exit.json`: исходная позиция бота сохранена, игрок ждёт на верхнем полу `[-780,-64,232.125]`. Критерии: событие platform_exit, затем cover_teammate на статическом верхнем полу. `TestBunk1RaisedPlatformExit` с локальными BSP/AAS проверяет выход и отказы для скрытой платформы, неверной высоты, полёта, обычного маршрута и отсутствия цели сопровождения.

Полный исторический эпизод пока не принят: в записи игрок стоял на выдвинутом мосту *99 (`origin.y=-250`), кнопки *98 и *104 были нажаты. Свежая карта без этих действий роняет актёра с исходных z=16.125 до -167.875. Попытки настройки сохранены в `workspace/artifacts/bunk1-upper-20260926` (baseline, buttons, buttons-walk).
