# Откуда берётся ошибка доводки

23.10.2026. Проверка после неудачного selective-execution confirmation. Цель — отделить вклад случайности от ошибки самого контроллера, прежде чем запускать новые игры или обучение.

## История и выбранная проверка

Уменьшение Gaussian yaw/pitch std в четыре раза уже проверено на 24 условиях: 8/24 → 5/24 побед, rules 13/24 (`combat_aim_feedback_experiments_20261021.md`). Полный deterministic ранее мешал смене оружия в recovery. Эти варианты не повторяются.

Новый опыт использует исходную `combat-conditional-fire-zero-v1-20261022` и её сохранённый TRAIN корпус `combat-conditional-fire-training-v1-20261022/corpus`: 32 боя, 5058 eligible policy rows. Validation/test не используются, новых боёв нет, параметры модели не меняются.

`diagnose_combat_aim_noise_cuda.py` воспроизводит всю историю на CUDA и вычисляет условный средний yaw/pitch с теми же выбранными target/mode, sampled movement и vertical. Переменные движения, позы, оружия и огня фиксированы. Для каждого реального MG-выстрела сравниваются геометрические лучи при исходном шуме, шуме ×0.25 и нулевом шуме. Поза, muzzle, наблюдаемая bbox-точка и фактическая отдача фиксированы.

Это одношаговая геометрическая диагностика в уже посещённых состояниях. Она не моделирует новые usercmd, движение/видимость цели, последующие кадры, integer-degree ballistic truncation/spread, попадания или победность.

## Проверки достоверности

Артефакт `combat-aim-noise-decomposition-v3-20261023/complete.json`, процесс завершён с кодом 0.

- Source weights/checkpoint/report и TRAIN metadata/streams связаны SHA-256; все cases имеют split TRAIN.
- Actor tensors совпали с checkpoint на CUDA; replay 5058 full-history rows. Максимальная ошибка native log-probability 0.0001414 при допуске 0.003; memory error 9.21e-6.
- Рассмотрено 1000 реальных MG-выстрелов в exclusive matched first-life alive provider windows без recovery. Для 932 выбранная наблюдаемая цель/bbox доступна; 68 без цели исключены, ближайшая цель не подставлялась. Диагностические shots распределены по 26 боям.
- Ветвь исходного шума совпадает с фактически предложенными углами; преобразование usercmd не меняло их сверх квантования. Native view согласован с applied action. Ни одного дополнительного исключения по этим условиям не потребовалось.
- Native aim/view/recoil печатаются через `%.6g`: максимальное отличие реконструированного исходного луча 0.000487°. Допуск 0.01° отражает точность телеметрии, а не требование побитного совпадения десятичных строк.
- v1 диагностики остановился на излишне строгом angular-formatting assert; v2 — на пропущенном JSON default `aim_mode=0`. Принят только полный v3. Никакого обучения или изменения исходных captures эти попытки не выполняли.

## Шум почти не меняет ошибку

| Группа | Shots | Исходный шум | ×0.25 | Без шума |
|---|---:|---:|---:|---:|
| Все измеренные |932|6,233°|6,201°|6,206°|
| Fine |854|5,304°|5,289°|5,288°|
| Coarse |78|16,404°|16,186°|16,260°|
| Ordinary |575|6,264°|6,199°|6,193°|
| Recovery |357|6,183°|6,205°|6,228°|
| В движении |751|6,592°|6,574°|6,582°|
| Стоя |181|4,742°|4,653°|4,648°|

В пределах 5°: 512/932 → 499/932 → 501/932. Без шума лучше исходного луча лишь 489/932 раз. Поэтому уменьшение среднего на 0,026° не является убедительным основанием для нового closed-loop опыта. Fine/coarse относятся к разным состояниям; таблица не доказывает, что принудительный fine улучшит бой.

Текущие `log_std` yaw/pitch около −3.90: latent sigma ≈0.0202, то есть примерно 0,30° на ось fine в ненасыщенной области tanh. Ошибка около 6° заметно больше этого масштаба. Из результата нельзя автоматически вывести, что шум нужно увеличить: это отдельная гипотеза с изменением TRAIN распределения.

## Отдача между наблюдением и выстрелом

`diagnose_combat_recoil_alignment.py` читает те же frozen shots; нейросетевых вычислений в нём нет. Средний native pitch recoil −7,96°, наблюдаемый −6,93°; средний signed delta −1,02°, mean absolute delta 1,18°. Это реальное различие текущего наблюдения и момента выстрела.

Однако добавочная oracle-компенсация **всего** этого delta при фиксированных view/muzzle/target ухудшает среднюю геометрическую ошибку: **6,233° → 6,344°**. Ordinary 6,264° → 6,387°; recovery 6,183° → 6,274°. В движении 6,592° → 6,776°, стоя 4,742° → 4,549°.

До native recoil ошибка 11,052°, после — 6,233°: имеющийся контроллер уже в значительной мере компенсирует отдачу. Средний signed pitch error после неё +0,264°, со знаками, различающимися по группам. Это не обоснование ещё одной общей поправки к pitch. Oracle тут только label-диагностика, не вход рабочего агента и не принятый учитель.

## Решение

Не запускать новый вариант с отключённым шумом и не добавлять общую компенсацию разницы recoil. Default и reward остаются прежними. Эти две простые причины не объясняют основную ошибку в проверенных состояниях.

Следующий путь: проверить представление **действия относительно наблюдаемой цели**. В нынешних fire/predictive inputs181 есть отдельные target coordinates и sampled yaw/pitch, но нет готовой величины их взаимной ошибки и нет observed recoil4. Linear181 может распознавать опасные состояния, но не обязан моделировать, как изменение углов изменит исход выстрела; большой MLP на этом корпусе уже переобучался.

Перед новым policy fit сравнить существующий predictive baseline с компактными causal action-relative geometry features (bbox angle/margins, ошибкой направления после candidate action, observed recoil/weapon phase). Все признаки должны вычисляться из наблюдения и рассматриваемого действия; native outcome остаётся только меткой. Проверки — прежние whole-battle seed/site folds, без увеличения сети и без runtime fire mask. Сначала проверить качество и чувствительность predictor к действию; только затем решать о его использовании в обучаемом контроллере. Предсказание успеха само по себе не считается улучшением боя.
