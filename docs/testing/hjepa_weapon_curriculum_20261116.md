# H-JEPA: последовательные пакеты обучения оружия

Продолжение `hjepa_weapon_onpolicy_20261116.md`. Первое обновление
на 64 TRAIN-боях изменило восемь запросов оружия на новом screen,
но не изменило ни один агрегированный боевой результат.

## Зафиксированный протокол

Корень: `workspace/artifacts/hjepa-weapon-curriculum-v1-20261116/`.
Три новых TRAIN-пакета offset 433, 434, 435; в каждом 16 миров,
четыре независимых потока, 64 боя. Одни и те же 16 дескрипторов
восьми карт, штатные случайные группы/инвентари. Условия каждого
следующего пакета не пересекаются с предыдущими.

После каждого пакета — четыре обновления только оружейной головы,
с тем же Adam 1e-4, clip 0.1 и behavior KL <=0.02. Температуру
повторно не увеличиваем: текущие logits переходят без пересчёта,
меняются только sampling seeds. Мотор/world фиксированы.
С учётом исходного пакета будет 16 optimizer steps на 256 боях.

Новый checkpoint `hjepa_weapon_onpolicy_update_v2` хранит алгоритм,
общий счётчик шагов, накопленные TRAIN seeds/входные SHA и ancestry.
`--previous-batch` принимает только завершённый пакет, проверяет
точное совпадение модели поведения с результатом прошлого пакета
и весов checkpoint с этой моделью, запрещает повторные seeds.
Adam и CPU/CUDA RNG продолжаются. `--resume` по-прежнему означает
продолжение того же пакета, а не допуск старых наблюдений к новому.

Исходный v1 checkpoint восстановлен новым кодом ровно теми же
четырьмя шагами на неизменных исходных данных. Перед запуском
серии проверено побайтовое совпадение модели с уже проверенной
`10caf3e869903a88f007627683a21b907c23b6125f5a4ed72ad057e87f424f02`.
Это перенос формата состояния, не дополнительное обучение.

Первый новый пакет отдельно проверяется как четыре шага против
двух шагов с `--previous-batch`, затем двух с `--resume`.
Проверка должна совпасть по модели, Adam, RNG и счётчикам/истории.
Модульные проверки также отклоняют повторный TRAIN мир,
чужую behavior-сеть, незаконченный пакет и несоответствие checkpoint.

Промежуточных TEST-оценок и подбора числа шагов нет. После третьего
пакета фиксируются веса и сравниваются на 16 новых условиях
test490/491: final, initial-onpolicy, keep, U1, rules (80 боёв).
Предварительный порог: минимум две дополнительные победы к keep,
не меньше побед, чем у initial; смертей не больше, чем у обоих;
полученный урон и урон себе не выше keep; valid capture/replay/mask.
Только при прохождении screen оправдан независимый repeat на 32
новых условиях. Основной U1 и предыдущие модели сохраняются.

Это проверка обучения выбора оружия при фиксированном моторе.
Устранение всех таймаутов и полноценный автономный бой требуют
отдельных подтверждений; замена условий успеха меньшим количеством
ошибок экспорта или численным совпадением не допускается.

## Завершённая серия

Три новых пакета приняты: 64 боя / 8 182 решения, 64 / 7 370,
64 / 7 856. Всего новых 192 боя / 23 408 решений; вместе с исходным
пакетом 256 боёв / 30 063 решения. Все 64 TRAIN-мира в цепочке
различны. Реальный Adam step=16 у всех шести тензоров оружейной
сети. Проверка межпакетного переноса плюс resume 2+2 совпала с
четырьмя шагами по всему checkpoint, включая Adam/RNG/ledger.
World, motor и все неоружейные поля точно сохранились.

шесть наблюдаемых смен, три после запроса; недоступных выборов ноль.
Нет доказательства исключительной роли нейросети вместо autoswitch.
Все 80 screen captures валидны. Продвижения и 32-case repeat нет.

Сдвиг вероятностей сети есть (до 0.20 на TRAIN-наблюдениях), однако
greedy-выбор изменился лишь на 157 из 23 408 учебных наблюдений и
не изменил наблюдаемую экипировку в новом screen. Продолжать такие
же короткие пакеты без изменения исследовательской гипотезы сейчас
необоснованно. Следующее направление — проверить исследование
длительных оружейных действий и корректное credit только в моменты
нового выбора. Старый greedy option16 уже давал отрицательный
результат; его нельзя объявлять решением или повторно подбирать
на этом TEST. U1, исходные веса и отрицательные результаты сохранены.
