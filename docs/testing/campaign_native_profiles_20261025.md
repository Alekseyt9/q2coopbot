# Профили корпусов и среды монстров

Проверка 25.10.2026. Новый генератор `campaign-native-profile-combat-v1` проверяет отдельные боевые типы в исходных точках их появления. Он дополняет проверенный генератор случайных групп, но пока не добавляет все новые типы в смешанные случайные составы.

```powershell
go run ./cmd/q2episode --root . --all-map-sites 1 --native-monster-profiles --out <fresh-catalog.json>
```

`--all-map-sites` здесь задаёт число участков на каждый местный боевой тип каждой карты. Чужие типы не подставляются. Схема сохраняет отдельные seed для train/validation/test/confirmation, исходный BSP SHA и случайный неполный инвентарь. Старые генераторы не меняют формат или условия из-за нового варианта.

## Реализовано

- Stock-профили 22 классов: исходные размеры, здоровье и среда из `SP_monster_*` Yamagi. Из них 21 класс реально встречается в BSP установленной кампании; Makron предусмотрен как профиль, но не добавляется искусственно на карты без его исходного класса.
- Наземные типы опираются на пол относительно своей нижней границы корпуса. Летающим пол не требуется. У Flipper проверяется вода у углов всего корпуса; лава/слизь исключаются.
- Проверяются полный AABB, взаимные пересечения, корпус игрока с `playerclip`, опора под углами, запас для `teleport` и динамические препятствия исходной карты.
- Исключаются пересечения с бочками, твёрдыми объектами и изменяющими движение триггерами. Для стартовой наблюдаемой цели проверяются центр, фактическая точка прицеливания, PVS и общая статическая BSP-область. Последняя проверка консервативна и не доказывает видимость сама по себе; видимость дополнительно подтверждается живым reset.
- Сценические `monster_boss3_stand`, `monster_insane`, `monster_commander_body` не подменяются боевыми врагами. Существующий `misc_insane` может оставаться частью окружения; его модель не является выбранной целью сценария.

## Живая проверка

Артефакты: `workspace/artifacts/combat-native-profiles-v1-20261025/` и `combat-native-profiles-recovery-v1-20261025/`.

Первый каталог содержал 208 рецептов. Для smoke заранее выбраны первые случаи каждой карты и каждого типа: 54 боя. Первая серия: 49 валидных, 5 технических отказов. Исходный `pool/report.json` остаётся `failed`.

Причины: невидимая на старте цель в трёх случаях и смещение игрока в двух. На `biggun` игрок попадал в `trigger_push`; на `city3` пересекался с бочкой. Проверки геометрии усилены. Новый каталог `catalog-v4.json` содержит 204 рецепта с явными `profile_missing`; число всех пар «карта–тип» не объявляется полностью покрытым.

Повторная серия: 5/5 валидных. Для четырёх исправлены условия того же типа. У Flyer на `biggun` допустимой точки пока нет: это ограничение сохранено; отдельная проверка покрытия карты использует её исходный Soldier SS. Этот случай не доказывает исправление Flyer на `biggun`.

Объединённый независимый аудит подтверждает 54 валидных capture: 38 карт, 21 точный боевой класс, 42 наземных/9 летающих/3 водных случая. Проверены native HP, начальные позиции, наблюдаемый упакованный bbox по правилам `SV_LinkEdict`, точный inventory reset и исполнение команд без recovery-команд. Подтверждения: `profile-verification.json`, `stock-profiles.json`, `audit.py`, оригинальные планы и отчёты.

На `fact3` нет монстров: синтетический бой не создаётся. Некоторые пары «карта–тип» остаются без подходящей точки; см. `profile_missing` каталога. Появление последующих фаз боссов и полное прохождение карты не проверены этим smoke.

NN-обучения и переключения рабочих весов не было. Главный реестр не менялся. Данные пока не имеют полного допуска для обучения награде; проверки стартов и исполнения не означают превосходство обучаемой модели над правилами.
