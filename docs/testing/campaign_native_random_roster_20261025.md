# Случайные местные группы и неполный инвентарь

Проверено 25.10.2026. Это проверка подготовки и выполнения боёв, не результат обучения или превосходства над правилами.

## Генерация

```powershell
go run ./cmd/q2episode --root . --all-map-sites 1 --native-random-roster --out <fresh-catalog.json>
```

Каталог охватывает 39 карт кампании, исключает deathmatch. Для `campaign-native-ground-roster-v1` поле `episode.monsters` задаёт допустимый пул, а `generator.roster` — его точную привязку и диапазон количества. Конкретный состав хранится в `task.instances[].monsters`: 2–4 монстра, выбор с повторениями. План и его проверка воспроизводят состав по seed. Каждый тип пула обязан присутствовать в исходном BSP этой карты; разновидности солдат не подменяются.

Состав, позиции и инвентарь используют раздельные потоки случайных чисел. Позиции резервируются для максимального количества, проверяются геометрия, пол, перекрытия и видимость основного противника. Имена старых генераторов и их диапазоны seed сохранены. Новая семья использует диапазон от 170 млн до 194 млн; четыре split остаются раздельными.

Текущие восемь типов помещаются в консервативный корпус `[-16,-16,-24]..[16,16,32]`: Infantry, Parasite, три Soldier, Gunner, Berserk и Brain. Корпуса и здоровье сверены с исходниками stock Yamagi и живым стартом. У Parasite верх корпуса ниже. Большие, летающие и водные типы пока не допускаются этим генератором: им нужны соответствующие проверки среды и корпуса.

Инвентарь: Blaster плюс 0–5 случайных дополнительных слотов, общий боезапас по шести типам патронов, включая ноль. Начальное оружие выбирается только из доступного; проверяются пороги SSG/BFG. Выдача точных 16 количеств выполняется командой `test_inventory_v1` только до выпуска тестовой сцены. Для запуска нужен явно выбранный движок с capability `initial_inventory_v1` через `Q2COOPBOT_DIAGNOSTIC_ENGINE_ROOT`. Это не разрешение менять инвентарь во время боя.

Победа требует отдельных убитых сущностей для каждой позиции состава. Дублированное событие смерти одного монстра не засчитывается за двух одинаковых. Серверное подтверждение старта также проверяет уникальность ID, точные типы, здоровье и позиции.

## Проверка

Артефакты: `workspace/artifacts/combat-native-random-roster-v1-20261025/`.

- Геометрия подготовлена для 35 карт, по одному участку на карту.
- 35/35 первых заранее выбранных seed прошли native capture и подтверждение старта; pool16, x2, исходники не менялись.
- 26 составов содержали повторяющиеся типы. Количество: 8 групп по два, 8 по три, 19 по четыре монстра; встретились все восемь типов.
- Правила завершили 17 целей. Проверены случаи с повторениями, включая четырёх `monster_soldier_ss` на `biggun`.
- 2590 игровых кадров, время пула 80,54 с. Это короткий технический smoke, не сравнительный тест качества.
- Подтверждения: `pool/report.json`, `roster-verification.json`, воспроизводимая проверка `audit.ps1`, исходные capture/report/DM2.

Четыре карты пока без рецептов этого генератора: `fact3` не содержит монстров, а `space`, `boss1`, `boss2` требуют других типов и условий размещения. Чужие монстры вместо них не подставляются.

Старый контракт наблюдений объединяет Soldier по модели, но уже передаёт сетевой skin для каждого противника; новая геометрическая схема не меняет формат входов весов. Точное имя native-класса отдельно хранится в условиях и серверном подтверждении.

Проверены пакет `internal/trainingepisodes`, компиляция CLI/бота и регрессии `test_combat_goal_stop.ps1`, включая повторяющийся класс и повтор одного события. NN-обучение в этой серии не выполнялось. Главный реестр не изменён: каталог и его диагностический реестр изолированы до завершения допуска данных и поддержки остальных типов.
