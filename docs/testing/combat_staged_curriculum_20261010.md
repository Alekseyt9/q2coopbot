# Two-to-three-enemy curriculum — 2026-10-10

The preceding joint and target-only group experiments did not improve held-out
success rate. This experiment changes the training curriculum; reward v8,
architecture, observation contract and normal all-head PPO remain fixed.
No runtime rule chooses the learned policy's target.

## Frozen design

Parent: `combat-group-training-processing-v1-20261010/update/` (group update8),
weights SHA `47fe9ecfe1cda616656c2000cae05e6dee8d91c424f9aaff4d358b727d2e536d`.
This is an experimental lineage, not a promoted live model. The unsuccessful
target-only branch is not used as a training parent.

1. Train64 new pair fights: Parasite+Infantry, four maps (base3,ware2,jail1,city1),
   two checked original encounter sites per map, two inventories (weapons and
   weapons-ssg), four train seeds per descriptor. Register16 recipes with split
   seed domains disjoint from three-monster recipes and other loadouts.
2. Resume the complete pair checkpoint and collect32 fresh own-policy trio
   fights: Parasite+Infantry+Gunner, both inventories on the four maps,
   train offset8/count4. This stage must use the updated pair weights.
3. Compare initial/final weights on exactly48 frozen validation fights:
   trio groups with both inventories (32 fights), and pairs at second sites
   with SSG (16 fights). Validation offset8/count4 avoids the preceding
   comparison sample. All stages use pool16, timescale2, independent seeds.
4. Native goal/death/start evidence and CUDA likelihood/memory checks are
   required. Preserve all deaths in training; do not select successful traces
   using held-out outcomes. Compare source/model/fixture hashes and do not
   promote a model from training returns or numerical checks alone.

Current training config remains `campaign-expanded-training-config-v1-20261010`:
actor LR3e-5, critic LR0.001, at most10 actor/40 critic steps per update,
joint approximate KL limit0.005. Each stage retains checkpoint optimizers,
RNG and consumed-rollout seals. Baseline capture can run while CUDA processes
stage1, but total live harness instances must remain16.

## Critic and credit-assignment audit

CUDA replay of the stage2 training histories against fixed pre-update GAE95
targets shows critic MSE5.19→1.37 and explained variance0.44→0.85.
This is training fit, not held-out critic accuracy; it does not indicate a
nonfunctional critic optimizer. Receipt:
`combat-staged-critic-credit-audit-v1-20261010.json`.

With gamma0.99/lambda0.95, an isolated TD residual50 ticks later receives
kernel weight0.0466; at lambda0.99 the corresponding weight would be0.3660.
At10 game ticks/sec, these are five-second delays. These values hold bootstrap
predictions fixed; actual learned value estimates also carry future effects.
Thus this is a candidate controlled experiment, not proof that present
training ignores late events. Next: explicitly fork the training config to
lambda0.99 while preserving reward/gamma/model/optimizer state, then test on
new validation seeds. Do not repeat parameter tuning on the48 fights above.
