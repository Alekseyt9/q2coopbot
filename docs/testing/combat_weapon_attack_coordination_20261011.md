# Связь смены оружия с удержанием огня

Новый weapon audit всех четырёх learned confirmation вариантов завершён,
по80 случаев. Запросы измеряются от `combat_policy.applied.weapon` до
наблюдаемого view-model; пропуски/смена владельца/конец записи цензурируются.
Это не время доставки UDP/reliable команды и не измерение native hits.

Показатели не доказывают одинаковой трудности каждого switching event:
политики выбирают разное оружие в разные моменты. Исчезновение21 keep frames
у parent — локальное улучшение, а не доказательство общего исправления всех
случаев гранат. У shared в этой выборке таких кадров изначально нет.

## Подтверждённая трасса и native код

Seed1228068000, parent-after job108 (победа), shared-after job268 (проигрыш).
Оба запрашивают Shotgun на102 и наблюдают его только на145:43 кадра.
Parent trace также логирует `weapon_request="use Shotgun"` на102.
С100 до130 MG gunframe циклически4/5, attack=true, Bullets уменьшаются:

gunframe7; на144 gunframe49; на145 наблюдается Shotgun с20 shells.

`F:/src/quake2/yquake2/src/game/player/weapon.c`, около650:
переход к WEAPON_DROPPING допускает newweapon лишь если state не
WEAPON_FIRING. `Machinegun_Fire`, около1308, выходит из непрерывной
стрельбы, когда BUTTON_ATTACK отпущен; при удержании продолжает4/5,
при отсутствии ammo завершает firing. SHA-256 этого файла совпадает с
native source record case manifest:
`59770b86786ebcda7c6239c28cdc42f6fbc9a0a882a6029f5d8b819498ee65ea`.

Это согласованное объяснение наблюдаемой задержки: удержание fire откладывает
смену, затем заканчиваются патроны. Трасса клиента не раскрывает точный
момент server acceptance/newweapon, поэтому дополнительно нужен native
контроль с одинаковым запросом и fire hold/release, а не заявление о полном
разборе всех43–44-кадровых случаев.

## Следующий шаг

Явный current weapon остаётся необходимым: v9 не различает MG/SSG/Grenades
при равных остальных полях. Для координации дополнительно нужен наблюдаемый
собственный last-request intent/его возраст и совпадение с текущим оружием.
Это клиентская история отправленной команды, не скрытый server newweapon.
Не выводить pending state из запасов, не выдавать предположение за native ACK.
Сбрасывать историю при смене map/spawncount/connection/life и смерти.

Подготовленный v10 current-weapon encoder ещё не подключён. Перед окончательной
фиксацией нового контракта решить, включить ли own-request history в тот же
новый suffix или отдельную следующую версию; сохранять старый префикс и
выполнять CUDA migration/no-training parity для выбранной ширины. Сам actor
должен выбирать отпускание огня; не подменять это правилом "при switch всегда
запретить attack". Native control сначала должен проверить влияние отпускания
при одинаковом оружии/fixture. Затем одинаковый full-actor PPO budget,
свежие own-policy histories, независимые switching и общие combat оценки.

Дополнительный сигнал:23–34 запроса уже экипированного оружия на80 боёв.
Оценивать их отдельно от успешных переключений; не автоматически штрафовать
каждый request, пока не различены полезный retry и лишнее повторение.
