# Экспериментальная награда боевого пилота

Дата: 05.10.2026. Реализован offline-расчёт `combat_reward_v1` для R2. Это заданная функция обучения, не подтверждение качества политики. Обученных весов, optimizer и PPO пока нет.

## Контракт

`q2combat-export --reward-config scripts/scenarios/combat-reward-v1.json` создаёт отдельные `rewards.jsonl` и `reward-config.json`. Старые observation/step/server-outcome файлы сохраняют собственные версии; награда не поступает в наблюдение Provider. Без явного reward-config scalar reward по-прежнему отсутствует.

Нужен `--synchronous`, подтверждённый reset с seed и точное исполнение каждого usercmd. Награда доступна только для первой жизни, соседних свежих наблюдений одного мира, согласованных идентичностей действия, одного native tick и полного exclusive dispatch. Truncated/handoff, хвост без next, последующие жизни и неподтверждённые эффекты получают `available=false`, `score=null`, причину отказа. Наблюдаемая смерть должна согласоваться с native-событием смерти. Данные диагностического Provider с наградой не превращаются в положительные демонстрации.

| Компонента | Коэффициент пилота |
| --- | ---: |
| Полезный урон здоровью живого монстра | +0.01 / HP |
| Полученный урон здоровью | −0.02 / HP |
| Дополнительный штраф за урон себе | −0.02 / HP |
| Урон здоровью напарника | −0.10 / HP |
| Смерть в первой жизни | −5.0 |
| Полный игровой tick | −0.001 |

Урон взят из фазовых native-событий, ограничен оставшимся живым здоровьем: overkill и урон трупу не увеличивают награду. Аптечка не отменяет полученный серверный урон и сама не даёт положительной награды. Урон себе входит также в received damage; дополнительный штраф намеренный. Tick — 0.1 игрового времени; x2 не удваивает награду за одно действие. Порядок суммирования фиксирован для воспроизводимости.

Победа, расход боеприпасов, урон броне, точность и отдельный бонус за kill сейчас не входят в scalar objective. Исчезновение врага не считается победой. Pilot с Blaster не проверяет экономику конечных боеприпасов. Коэффициенты экспериментальные: их нужно сравнивать по validation и метрикам первой жизни, а не объявлять оптимальными. Проверка знаков и конечности коэффициентов не доказывает отсутствие всех способов эксплуатации награды.

## Прогоны и проверки

Команда использует существующий харнес, четыре независимых сервера/клиента и два холодных эпизода на worker, с восемью разными seed:

```powershell
./scripts/run_learned_combat_baseline.ps1 -Workers 4 -EpisodesPerWorker 2 -Timescale 2 -GameFrames 300 -Loadout blaster -CombatMode learned -Synchronous -Mixed -HealthKit -RewardConfig scripts/scenarios/combat-reward-v1.json -Seed 11600 -Port 32988
```

Runner сохраняет SHA256 и содержимое коэффициентов в manifest и проверяет неизменность файла во время прогона. Exporter report содержит число доступных reward-шагов, сумму и причины маскирования. Сумма по разным эпизодам служит диагностикой; она не означает долю побед.

Unit-проверки охватывают составную стоимость, native death, аптечку при полученном уроне, исключение respawn/handoff/gap/неполного dispatch/чужого outcome, устаревшее окно эффектов и некорректные коэффициенты. `go test ./...` прошёл.

Live-артефакты: `workspace/artifacts/learned-combat-baseline-20261005-181115-471/`. Все восемь captures пригодны, provenance и синхронное исполнение подтверждены; 46.64 секунды с холодными стартами и экспортом, 19.49–19.89 игровых кадров/реальную секунду. Из 2005 экспортированных переходов награда доступна для 429; 1576 переходов после первой жизни исключены. Первые смерти учтены, награда диагностического Provider отрицательная; gameplay acceptance — 0.

Это проверка воспроизводимости расчёта по одному логу, не доказательство идентичного мира при двух независимых стартах.
