## Gaussian noise на реальных MG выстрелах

Все **122** реальные MG bullets before/update10 найдены по exact matched native windows первой жизни после native GAME frame100. Для112 есть выбранная наблюдаемая цель и её точный native bbox в момент выстрела; по5 кадров без выбранной видимой цели на вариант исключены из геометрической части, ближайшая цель не подставлялась. Все112 действительно имели active25-way aim event.

`mg_noise.py` сначала использовал observed point, затем `mg_noise_shot_pose.py` проверил **shot-time native pose**. Удерживаются muzzle/view/actual recoil/поза/цель/кандидат; Gaussian yaw/pitch меняются на исходный шум, четверть и conditional mean. Native poses — только offline labels, не policy inputs. NN вычисления только CUDA. Строки не становятся PPO/BC данными.

## Поддержка существующих действий

`mg_support.py` проверяет **все25** текущих вариантов `[0,-5,-2.5,2.5,5]²` вокруг того же оригинального Gaussian source. Поза и native muzzle/recoil удерживаются; ограничение режима и clipping воспроизводятся. Выбранный вариант совпал с исходным запросом. `c[77]` здесь — флаг текущего Machinegun в conditional context (73 common + weapon index4), поэтому речь именно о MG-eligible кандидатах, а не о SG или любом оружии.

Дополнительно проверяется ориентир, вычисленный только из текущих наблюдаемых bbox/позы/current recoil и centered MG muzzle (`viewheight-8`). Никакие shot-time native координаты не участвуют в его построении. Отдельно помечается выход за диапазон текущего режима; он не выдаётся за доступное действие.

| Состояния update10 | Выбранный луч пересекает bbox | Хоть один из25 пересекает | Ни один из25 не пересекает | Наблюдаемый ориентир внутри режима пересекает |
|---|---:|---:|---:|---:|
| Fine,23 shots | 17 | 20 | 3 | 14 |
| Coarse,33 shots | 5 | 9 | **24** | **26** |

В18coarse состояниях наблюдаемый ориентир пересекает bbox, а весь текущий grid — нет. Это **ограниченность локальной поддержки при фиксированной позе**, не доказательство, что новый вариант попадёт в движке либо улучшит бой. При изменении yaw изменяется world movement, потому нужен native paired pilot; нельзя просто использовать future-muzzle inverse labels как оптимальное действие.

Новый `diagnostic_anchor_probe` сохраняет исходные Gaussian/categorical/fire/movement выборки. Только на указанном кадре возвращаемые yaw/pitch заменяются ориентиром из текущих наблюдаемых bbox, позы и kick; для MG используется центральное положение дула на 8 units ниже глаза. ### Почему исходный gate остался rejected

Первоначальный V1 требовал полного совпадения файла с историческим capture и полной одинаковой длины identity. Он **не прошёл**, отчёты не переписаны. На mintro/waste3 исторические ID сущностей отличаются уже в первом наблюдении; они не перенумеровываются и historical parity не объявляется доказанной. На mine4/bunk1 identity расходится только после одинакового native goal: асинхронная остановка пишет разное число post-goal кадров.

Отдельный post-hoc V3 проверил точные current baseline/identity записи в уже определённой сервером первой жизни, а для anchor — точный полный префикс и исходное sampled событие на root. Все восемь пар прошли. В UI/debug `first_life.last_frames.visible_enemies` канонизирован только порядок по неизменному ID; реальные policy observations, slot order, IDs, commands и значения не сортируются и не нормализуются. Два metadata regression test проверили, что реальные изменения внутри боя, ID и health не скрываются. V2 отказ и первый V3 сбой strict provider-only reporter также сохранены; последний выявил реальный hybrid suffix на waste3. Короткие горизонты теперь исключают команды после подтверждённого terminal и помечают owner.

Закрывающий артефакт: `workspace/artifacts/combat-anchor-other-maps-native-v1-20261026/analysis-v3/analysis-complete.json`. Детали: `summary.{json,md}`, `comparison.json`, `branch-effects.json`, `continuation-first-life.json`, `cuda-batch/report.json`. `original_protocol_passed=false`, `posthoc_scope_correction=true`, `quality_confirmation=false` остаются явными.

Все 24 случая, включая baseline controls, опубликованы только через `diagnostic-index.json`: производные reports имеют `diagnostic_only=true`, `ordinary_training_eligible=false`, `ppo_training_ready=false`. Исходные numerical proofs и raw reports сохранены; большие неизменяемые streams разделяют дисковое хранение через hardlinks. Никакой PPO fitting/merge по этому опыту не выполнялся.

Следующий новый механизм — **обучаемый выбор дополнительного широкого направления прицела** рядом с существующими вариантами, с возможностью отказаться от него. Порядок реализации: отдельная версия события/likelihood, точная совместимость при отключённом варианте, CUDA migration/replay, затем небольшой matched TRAIN опыт с целевой метрикой всего боя и отдельными source/rules проверками. Постоянное наведение не включается; прежние отрицательные fine-only/shared residual, commitment/miss penalties и multi-step effect forecaster не объявляются отсутствующими и не повторяются без нового механизма.
