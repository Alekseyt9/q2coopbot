## Диагностическая подмена только прицела

Добавлен явно экспериментальный `diagnostic_nominal_aim`, по умолчанию выключен. Он доступен только для captured synchronous learned fixture; обычный coop и training plans его не принимают.

Контроль — исходные checked weights с прежним шумом. Кандидат получает тот же файл весов и дополнительное вмешательство в исполнение. Правила — третий вариант. Это диагностика предела выбранной постановки, не новый обученный агент и не идеальный верхний предел.

На Machinegun/Shotgun/Super Shotgun вмешательство наводит на bbox-aim-point уже выбранной моделью наблюдаемой цели, учитывая известные текущие kick angles. При отсутствующей/закрытой цели, неверном track или неизвестном bbox исходная команда сохраняется. Blaster и остальные неподдерживаемые здесь виды оружия остаются под исходным прицелом модели: упреждение снаряда в этот опыт не входит.

Выбор цели, оружия, attack и вертикального действия сохраняется. Горизонтальная команда пересчитывается в новую систему взгляда с сохранением мирового направления; если компоненты превышают400, применяется общее масштабирование. Последующие проверки столкновений и огня сохраняются. Это неизбежное ограничение чистоты опыта: скорость может уменьшиться при насыщении команд, исполнение зависит от нового направления взгляда. Реальные эффекты проверяются телеметрией.

Модельный sample/proposed command сохраняются исходными. Вмешательства помечены `diagnostic_nominal_observed_aim` и `diagnostic_aim_view_basis`; applied command отражает реальное исполнение. Этот опыт нельзя представлять как улучшение полностью обученной политики или использовать как обычный PPO corpus без отдельной постановки обучения с учителем.

Первый smoke:24 боя,8 условий на вариант (4 ordinary+4 recovery), validation offset540, selection seed20261021, порт42200, пул16 ×2. Спецификация `combat-nominal-aim-smoke-spec-v1-20261021.json`; root `combat-nominal-aim-smoke-evaluation-v1-20261021`. Результат добавляется после завершения проверок; старт процесса не является доказательством эффективности вмешательства.

Smoke v1 выявил ошибку реализации: проверялись текстовые названия оружия, но наблюдения содержат пути моделей. Не было ни одного диагностического вмешательства. Native/CUDA записи корректны как записи исполнения, однако опыт не проверил заявленную гипотезу; качество метода по нему не оценивается. Отдельный receipt `diagnostic-activation-rejected.json` сохраняет отказ. Исправлено через существующий `directHitscanWeapon`; тесты дополнены всеми тремя реальными protocol paths. Новый reporter отклоняет диагностическую ветку без фактических вмешательств; этот отказ проверен на v1 до создания bundle completion.

Повторный smoke v2 использует свежий validation544 и порт42300; root `combat-nominal-aim-smoke-evaluation-v2-20261021`, spec `combat-nominal-aim-smoke-spec-v2-20261021.json`. До проверки вмешательств и полного seal результат не считается оценкой эффективности.

Аудит проверяет именно trace: стандартный execution summary ранее агрегировал только attack/movement причины, поэтому отсутствие yaw в его словаре не означает отсутствие вмешательства.

MG measured rays, ordinary: средняя post-recoil ошибка6.23→4.01°, native damage выбранной цели29/65→34/67 rays. Recovery:7.12→10.88°, damage выбранной цели42/79→49/78. Это разные траектории и наблюдаемые poses, не контрфактическая оценка каждого выстрела. Номинальная геометрическая доводка не обеспечила равномерного улучшения и не является доказанно качественным учителем. Большие повороты10.45→15.13%, смены цели30.45→37.07/100 кадров; более точное направление на отдельном кадре не означает лучшую общую координацию.

**Следующее решение:** не назначать диагностическую подмену рабочим боем и не обучать модель слепо копировать её. Для нового обучаемого контроллера подготовить отдельный свежий train corpus с историей наблюдений, исполненными командами и временем между наблюдением/командой/выстрелом; проверить метки recoil/упреждения по native событиям. Будущее состояние допустимо как учебная метка, но не как вход рабочего агента. Сначала сравнить удержание и прогноз движения одной цели при собственном страйфе; затем добавить группы и выбор цели. Эти новые обучение и корпус в данном цикле ещё не выполнены. Оценочные бои из этого документа в обучение не включаются.

## Реализация и проверки

Проверяет исходный spec/evaluation seal, бюджет, CUDA cases, SHA результатов; сохраняет диагностические labels отдельно. Скрипт сам не запускает NN или обучение. Проверен на ранее завершённом smoke и новом72-case screen.

Новые целевые Go tests проверили сохранение мирового движения при изменении взгляда, работу protocol delta angles, сохранение/невыдачу огня, отказ при неверном track/закрытом или неизвестном bbox/снарядном оружии, запрет режима в обычном coop. Пройдены `go test ./internal/bot -run '^TestDiagnosticNominalAim' -count=1` и metadata tests `go test ./internal/trainingepisodes -run 'TestGenerated' -count=1`; NN в этих тестах не исполняется. Проверен синтаксис изменённых PowerShell runners и Python entrypoints.

После диагностики следующий выбор — обучаемый контроллер доводки с проверенными метками/обратной связью. Часть нужных признаков и spatial residual уже реализована; не объявлять повторное добавление существующих полей новой архитектурой. До обучения нужно закрепить, какие ошибки исправляет новый контроллер и каким измерением это проверяется.

`scripts/export_combat_aim_feedback.py` связывает выстрел и pose с точным эксклюзивным unrecovered command window, только с явно выбранной наблюдаемой целью и её track.
