# Base1/base2: Update26 против обычного Go-контроллера

Дата: 07.10.2026. Проведено 16 учитываемых native эпизодов: по четыре seed для каждого контроллера на каждой карте. **Обычный контроллер прошёл 7/8 эпизодов, обученная система — 1/8. Update26 не принят для замены обычного боя на полных картах.** Это проверка переноса обучения из подготовленных боёв, а не обучение на этих картах.

## Условия

- Четыре одновременно работающих выделенных сервера и Go UDP-клиента, loopback, timescale 2, skill 1, coop solo. Существующие native runtime, BSP/AAS и damage telemetry harness.
- Каждая карта запускается независимо с обычной стартовой позиции, 100 HP и штатным инвентарём. Это не цепочка с переносом оружия из base1 в base2. Исходные монстры, предметы, двери и кнопки сохранены. cheats 0; без teleport/give/kill, бессмертия, добавленных монстров или scripted movement.
- В обоих вариантах одинаковый Go-планировщик маршрутов. Rules управляет обычным боем; learned передаёт бой PPO и записывает причины возврата к правилам. LLM отключены.
- До 1800 игровых кадров (180 игровых секунд). Успех — наблюдаемая native смена на следующую карту: base1→base2 или base2→base3. Респавны разрешены, поэтому успех не означает прохождение без смертей. Возврат в предыдущую карту — неуспех.
- Base1 seeds 44900–44903; base2 seeds 45000–45003. У каждого эпизода свой seed; соответствующие rules/learned эпизоды имеют один seed. Асинхронный сетевой момент подключения и полный engine state не синхронизированы: это сравнимые seeded запуски, не доказанная побитовая воспроизводимость мира.
- Выбрана последняя наиболее долго обучавшаяся ветка: **Temporal attention Update26**, 26 updates / 249 actor steps, V6/845 признаков и masked weapon head. Attention по 32 кадрам, 4 heads, без GRU. Это не утверждение, что Update26 — лучший по качеству checkpoint.
- Исходные веса: `workspace/artifacts/combat-multiweapon-v1-20261007/update-26/weights.json`, SHA256 `b7e3b60bfc17bea5fd38c8c8acc35af881702082d1a0ffac47d5a454f5bb7062`. Копия для оценки имеет deterministic=true; остальные веса сохранены. Оптимизации/обучения в этом опыте нет; inference выполняет Go.
- В учитываемых трассах оба контроллера стреляли Blaster. Дополнительное оружие не выдавалось. Эта оценка не доказывает полезный выбор между MG/Shotgun: текущий training curriculum в основном использовал подготовленные бои с выданным MG.

## Что действительно управляло боем

Provider владел 4491/6748 кадров base1 (**66.6%**) и 3899/4421 кадров base2 (**88.2%**), считая всё время на карте, включая перемещение вне боя. По отдельным seed base1: 60.82%, 62.52%, 71.68%, 69.74%; base2: 84.58%, 87.73%, 90.62%, 89.12%.

Это не исключительно rules fallback под названием learned. Основной возврат к Go на base1 — `system2_noncombat`; также зарегистрированы смерть/устаревшее наблюдение, visibility timeout и превышения inference budget 5 мс. Полные причины и числа находятся в per-run reports. Часть действий provider ограничивается записываемыми проверками препятствий, движения и безопасности стрельбы; provider ownership не означает отсутствие этих вмешательств. Не поддерживаемое оборудование по-прежнему возвращает бой правилам; в этих эпизодах использовался Blaster.

Зафиксированы два native ухода в base1 во время эпизодов learned на base2. Это показывает проблему связи боевого маневрирования с целью маршрута; не считается прохождением base2. Причины низкой точности и смертей требуют отдельного разбора: таблица показывает слабый перенос, но не доказывает, какая часть архитектуры его вызывает.

## Доказательства и исключённые попытки

- Base1: `workspace/artifacts/combat-campaign-comparison-v1-r2-20261007/report.json`, только четыре rules и четыре learned результата с map=base1.
- Base2: `workspace/artifacts/combat-campaign-base2-v2-20261007/report.json`.
- Объединение 16 учитываемых эпизодов: `workspace/artifacts/combat-campaign-base2-v2-20261007/comparison.json`. В подкаталогах каждого эпизода: config.json, bot.jsonl, server.log, report.json.
- Обе завершённые серии имеют source_unchanged=true; все 16 учитываемых эпизодов infrastructure_ok=true. Это принятие захвата и подсчёта, а не приёмка качества learned.
- Native q2ded.exe SHA256 `4327977bc061b8ec96357240850a6ae1d6e5a41903dc1fddb8c8b0a16fe014ce`; game.dll SHA256 `c7b2a7b631406f4f0c8db37a9a6ad44811bd9b1ff8f9df9227a3ccb8e66ada16`.
- Урон/убийства взяты из native damage events, с attribution bot entity и фильтром оцениваемой карты. Урон ограничен живым HP цели, убийство требует перехода HP>0→HP<=0. Серверная телеметрия служит анализу, не наблюдениям модели. Смерти — переходы наблюдаемого HP, повторяющиеся кадры исключены.
- Первая попытка `combat-campaign-comparison-v1-20261007` не стартовала: PowerShell запрещает передавать scriptblock через using в ForEach-Object -Parallel. Исправлено восстановлением worker из текста, материалы сохранены.
- **Восемь base2 из v1-r2 исключены.** Ошибка runner: next_map-only выбирает другой выход, чем существующий campaign_route, и оба контроллера стояли на старте без боя. Исправлено использованием route `[base2,base3]`, затем повторены все восемь base2 в v2. Base1 из v1-r2 имеет один требуемый выход и учтён.
- У base2 learned 45000/45002 начальный collector ошибочно назвал остановку `frame_budget`. После завершения причиной установлено `native_wrong_exit` по native map rows и wrong-exit.json. Данные карты не изменялись. Ожидание на неправильной карте прекращено stop_file; runner теперь автоматически заканчивает эпизод при любом native выходе и различает правильный/неправильный.
- PAK/BSP/AAS связаны hardlink, без новых отдельных копий PAK на каждый эпизод. Все процессы этих серий завершены; пользовательский Yamagi не запускался и не прерывался.

## Изменение запуска и проверки

`test.campaign_combat_evaluation=true` позволяет локальную оценку PPO на натуральном campaign старте без аренного teleport. Требует loopback, frame pacing, capture, конечный frame budget и отключённые LLM/fixture overrides; обычные правила запуска learned вне этого opt-in сохранены. Это не переключение live/default. Локальный PPO загружается напрямую; remote pilot по-прежнему требует synchronous fixture.

Runner: `scripts/run_learned_campaign_comparison.ps1`; параметры Model, OutputRoot, Workers=4, GameFrames=1800, Skill=1, Maps=base1/base2. На base2 обязательно используется campaign_route. Модель в режиме оценки заморожена и детерминирована.

`go test ./cmd/... ./internal/...` прошёл, включая изоляцию нового режима. `go test ./...` запущен и завершился ошибкой из-за прежних нескольких main в сгенерированных каталогах `workspace/artifacts/temporal-mixed-demo-20261006` и `workspace/artifacts/combat-mobile-recoil-aim-v1-20261007`; продуктовые пакеты прошли. PowerShell parser ошибок не обнаружил.

Далее требуется обучение/оценка против состава монстров этих карт и с обычным Blaster стартом, а также связь боевого движения с маршрутом и опасными выходами. Простое увеличение числа updates на прежнем MG/Parasite fixture пока не доказано как решение. Rules остаётся рабочим контроллером полного прохождения.
