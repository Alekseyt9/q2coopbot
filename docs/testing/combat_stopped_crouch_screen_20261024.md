## Изменение

`test.stopped_crouch_probe_all_frames` включает тот же проверенный helper на протяжении первого life после combat release. Он сохраняет только отрицательный Up, выбранный моделью, после полного горизонтального stop и успешного подробного Pmove/path check. Не выбирает новую позу или направление прицеливания. Геометрические ограничения не ослаблены. Флаг несовместим с однокадровым режимом, требует loopback/captured/synchronous/learned/combat-only сессии; в обычном coop отключён.

Режим доступен через реестр (`q2episode --diagnostic-stopped-crouch`) только для learned evaluation. План train/rules с ним отвергается. Флаг передаётся через существующий пул до worker, config, capture manifest, native export и CUDA metadata. Такие данные имеют отдельную diagnostic version; обычный PPO fitting и merge их не принимают. CUDA processor проверяет каждый случай отдельно и не создаёт объединённый учебный корпус. Общие веса и default guard не меняются.

## Следующая гипотеза

Исправление только позы затрагивает малую часть отмен движения. Следующий технический вопрос — какие запрошенные моделью горизонтальные перемещения обычный guard отменяет, хотя подробный Pmove и прежние path checks их допускают. В уже закрытой offline реконструкции имеются63 таких proposed paths; это кандидаты, а не разрешённые native движения. Сначала проверить их входы и причины отказа на прежних TRAIN записях, затем зафиксировать небольшой однокадровый native тест до просмотра исходов. Не ослаблять ограничения на опору/препятствия, не объявлять каждую отмену ошибочной и не использовать held-out неудачи для fitting. Цель — согласовать выбранные движение/позу/прицел с фактическим исполнением; общее превосходство над rules остаётся недоказанным.
