# Attack/weapon/target learning experiment (2026-10-10)

## Motivation and implementation

Recent joint updates change mostly continuous aim and movement. A prior
target-only update changed target probabilities but did not improve held-out
group success. This experiment trains attack, available weapon and target
together, retaining the parent actor's aiming and movement behavior.

`ppo_recurrent.py --actor-head-scope decisions --decision-head-lr .003
--fork-head-scope` selects attack output4, weapon outputs8:20 and target
outputs20:29 in both base and attention/GRU output tensors. All other actor
parameters, spatial branch and log standard deviations are frozen. Projection
restores inactive output rows and Adam moments after each candidate step,
including repaired fallbacks. Entire optimizer states of inactive tensors
are preserved. Shared output tensor Adam clocks advance for the selected
updates. Rejected trials restore the full candidate state. Changing scope
or its learning rate requires an explicit checkpoint fork.

The on-policy PPO objective, masks, reward, critic updates and joint KL guard
remain unchanged. This is a combined intervention (restricted actor scope
and a larger decision learning rate), not an isolated causal test of only
freezing or only learning rate. No weapon/target heuristic or demonstration
label is added; reward-driven sampled actions determine the update. Vertical
actions and aim-mode decisions stay frozen along with continuous outputs.

Three GPU tests pass: factorized masked KL, preservation of target-scope
inactive outputs/momentum and rejection rollback, and preservation of
decision-scope inactive outputs/momentum for output widths45 and81.
The GPU CLI integration test also passes two successive ordinary updates
and resume/export checks for GRU, Temporal Attention and Entity Attention;
the default joint-training path remains compatible.
