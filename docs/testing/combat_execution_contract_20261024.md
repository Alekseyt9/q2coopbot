## Проверяемая гипотеза

После дообучения при том же исполнении действий, что используется при оценке, модель сможет лучше использовать восстановленные допустимые движения. Контрольная ветка получает тот же объём дообучения при прежнем исполнении. Это проверяет адаптацию к среде; предположение о причине предыдущего ухудшения пока не доказано.

## Контракт

`combat_execution_contract` принимает `legacy_v1` либо `checked_ground_crouch_v1`. Отсутствующая/пустая историческая метка означает legacy. Неизвестное значение отвергается. Метка присутствует в весах, runtime config, registry plan, manifest, native/CUDA metadata, training config и dedicated checkpoint scope.

Новый режим включает ту же последовательность helpers, что была проверена диагностическим screen: подробная проверка исходного наземного запроса после unsupported-motion stop, затем сохранение crouch при оставшемся горизонтальном stop. Aim/fire/weapon команды helpers не добавляют. Прыжки/воздушное ускорение/другие причины отказа движения не разрешаются. Все прежние path checks сохраняются.

До отдельной приёмки checked contract разрешён только в captured/local/synchronous/learned/combat-only fixture с checked wall slide. Диагностические flags с ним не смешиваются. Обычный coop/default остаётся legacy. Веса нового контракта не загружаются в runtime другого контракта, native exporter сверяет config/manifest/model, CUDA finalizer также проверяет contract, merge и fitting отвергают несовместимое сочетание.

Диагностические held-out записи прежних опытов остаются запрещёнными для fitting. Новые TRAIN данные собираются собственными политиками в явно заявленных недиагностических тренировочных средах; контракт исполнения не меняется между сбором, обучением и оценкой конкретной ветки.

## Инициализация на GPU

Обе ветки происходят от одного endpoint4e31f0c1… и checkpoint67baa292…. `initialize_combat_execution_contract_cuda.py` проверяет на CUDA совпадение actor/value/std с JSON весами, добавляет только метку контракта и сохраняет новую область checkpoint/optimizer `combat_execution_contract_ppo_v1`. Активный пятигрупповой Adam копируется из проверенного decision-scope состояния. Прежние optimizers/history сохраняются anchors; счётчики собственных обновлений нового scope начинаются с0, общие счётчики обучения не сбрасываются.

Обе CUDA миграции закрыты: learned tensors, optimizer states и RNG сохранены; checkpoint roundtrip exact; старые/default trainer scopes новые checkpoint не принимают. JSON SHA меняется из-за метки, а не нового обучения. Legacy initializer weights6a1aa036…, checked initializer d552f262….

Первая спецификация ошибочно задавала train offset6000, тогда как зарегистрированный TRAIN диапазон имеет count512. Ошибка найдена до игр/fitting; сохранены только два initializer receipts v1. Активный протоколv2 использует offset400 с дальнейшим поиском свободных зарегистрированных сидов по истории. Это preflight correction, а не переигрывание исходов.
