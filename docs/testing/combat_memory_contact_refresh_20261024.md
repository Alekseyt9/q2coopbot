## Следующая отдельная гипотеза

Закрываем этот короткий frozen-followup movement teacher как неподтверждённый общий сигнал. Далее проверяется другая постановка управления: временная обратная связь от предыдущей реально исполненной команды движения. Не ещё один подбор направления по одному удачному исходу.

Протокол `combat_action_inertia_protocol_20261024.json`: одноρ0,65, источник/noise-only/inertia/rules. Meanдвижения0:2после существующегоmotor преобразуется изжелаемогоtanh(mean) и предыдущихsentforward/side/400 с весами0,35/0,65, затем возвращаетсяatanh; бинарноеclampε=2^-12. Это сохраняет локальные координаты команд, не гарантирует постоянное направление в мире при повороте камеры. Углы/target/weapon/fire-logits сами не сглаживаются; их существующая связь с новым сэмплированным движением остаётся.

Movementstd0:2умножаетсяsqrt(1−ρ²); noise-only получает ровно такоежеизменениеstd,но прежнийmean. Так различаются эффект меньшего шума и эффект обратной связи. Это правило бюджета шума, не доказательство одинаковой стационарной дисперсии в нелинейной игре. Рho0короткозамыкается к точному исходнику. Скрытое состояние случайного шума не вводится: предыдущая команда уже есть в наблюдении, поэтому будущая conditionalGaussianплотность может считаться по текущему состоянию. Runtime/PPOresumeподдержка требует отдельной приёмки.
