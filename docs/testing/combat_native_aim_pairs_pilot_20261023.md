## Проверка причинности

Все20/20 сравнений приняты. Baseline воспроизвёл прежние source actions/features и исход реального выстрела во всех4состояниях. Проверены полный physical prefix, encoded features, actor memory, исходные Gaussian/discrete draws, предыдущие команды и head timing в момент вмешательства. Сырые enemy ID и их ссылки сопоставляются явной стабильной bijection; остальные поля не удаляются. Native spread проверяется при одинаковом water/muzzle path. Labels строятся только по фактическому native выстрелу, а не по predicted hit score.

HP здесь — фактическое уменьшение здоровья монстра в native событии, ограниченное его живым HP до выстрела. Это разные состояния и механики контакта; считать номинальный weapon damage вместо измеренного результата нельзя. Это не средняя точность и не победность модели.

Сбор содержит нужные разные отношения: полезное вмешательство, вредное вмешательство и равные действия. В ware2 site02 не проверены остальные20направлений, поэтому нельзя говорить, что выстрел невозможно исправить всей сеткой. На base3 site02 совпадение immediate damage не доказывает одинаковую долгосрочную полезность.

## Формат для следующего обучения

`combat-native-aim-pairs-proof-v1-20261023/labels.jsonl`:4контекстных записи, всего144092байт. Каждая содержит реальные1147features, исходный sample,25predictor hints и только принятые альтернативы с native outcome/health damage/delta относительно baseline. Метки отделены от policy inputs. Тип `combat_native_aim_pair_labels_v1` явно не является обычным on-policy PPO rollout.

Четыре состояния недостаточны для обоснованного обучения с переносом. Следующий ограниченный этап: использовать другие подходящие моменты уже закрытых16траекторий и собрать дополнительные пары; проверенные старые метки сохранить. В имеющихся данных11боёв содержат подходящие состояния. Цель первого расширения — около16контекстов по4геометриям, не более2на один seed. Если нужный баланс недоступен, показать фактическое покрытие, не подменять его обещанием.

До fit зафиксировать разделение по seed/боям, чтобы соседние состояния одной траектории не оказались по разные стороны проверки. Затем отдельный GPU supervised fit головы: сохранить baseline при равном/лучшем реальном результате и учить альтернативу там, где она помогает. Контроли — исходная голова и постоянное распределение с теми же средними частотами. Реальные бои на свежих validation seeds потребуются отдельно: fit и heldout loss не доказывают превосходства над rules.
