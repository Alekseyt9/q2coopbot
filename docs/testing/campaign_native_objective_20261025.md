# Нативное завершение боя и регистрация кампании

Проверено 25.10.2026. Случайные составы используют только точные классы монстров из исходного BSP соответствующей карты. Основной тип сохраняется; дополнительные типы, повторения и доступное оружие с общими боеприпасами выбираются по seed. Deathmatch исключён.

## Реестр

В `scripts/scenarios/combat-training/index.json` добавлены 204 рецепта `campaign-native-habitat-roster-v1` на 38 картах. Всего 612 описаний, включая прежние запланированные и исторические записи; это не 612 полностью допущенных учебных сценариев. Исходные 408 файлов сохранены. Добавленные JSON занимают 5 535 911 байт.

Все 612 описаний прошли строгий Load; для каждого нового рецепта построен экземпляр train с одним seed, включая проверку классов по исходному BSP и размещение. Это не означает живую проверку каждого из 204 рецептов. Предыдущая проверка подмножества: 53/53 capture, 145 акторов, 38 карт. `fact3` не содержит исходных боевых монстров и не получает искусственного состава. Неподходящие пары карта–тип остаются недопущенными.

Артефакт регистрации: `workspace/artifacts/combat-native-curriculum-registration-v1-20261025/`, включая frozen registry, plan, preparation и registration receipts. SHA256 нового индекса: `5e21e74e2021ada3d892a3264acb9566b61989a53f7384bbf65c27064ecd9d57`.

## Жизненный цикл цели

Новые рецепты требуют `require_native_objective=true`. Победа требует подтверждённых убийств исходного состава, живого бота и нулевых счётчиков живых боевых акторов и ожидающих фаз на точном кадре следующего наблюдения. Счётчики независимо читаются из исходного серверного лога; устаревший, чужой или отсутствующий кадр не принимается. Для Jorg учитывается анимация смерти и задержка появления Makron. Проверка обычного v1 receipt не принимает v2 без отдельного нативного доказательства.

Нужен диагностический engine с capability `combat_objective_v1` и `initial_inventory_v1`; проверенная неизменяемая сборка: `workspace/artifacts/combat-objective-engine-v2-20261025`. В запуске задаётся `Q2COOPBOT_DIAGNOSTIC_ENGINE_ROOT` на эту папку. Обычный установленный runtime не заменён.

Подтверждения:

- `combat-objective-lifecycle-probes-v3-20261025`: настоящий Medic воскресил Infantry с тем же ID (кадр 20 смерть, 751 воскрешение). После смерти Jorg на кадре 20 до появления Makron на кадре 76 не было преждевременного нулевого состояния цели.
- `combat-objective-harness-v1-20261025`: 8/8 capture; шесть фактических v2 побед независимо проверены Go-валидатором по сырым логам.
- `combat-objective-frozen-policy-ab-v2-20261025`: одна замороженная обученная политика, фиксированные seed, наблюдатель выключен/включён. Совпали 292 общих наблюдения и команды, все 289 полных следующих состояний и границы побед. Два различия в неполных хвостах закрытия процесса сохранены в исходном отчёте.

Ранее выполненный A/B на правилах не доказал идентичность траекторий: команды контроллера расходились. Этот отчёт сохранён как неуспешная проверка идентичности, вывод заменён ограниченной проверкой замороженной политики выше. Неуспешные probe v1/v2 и первая попытка deterministic-копии модели также сохранены.

## Допуск обучения

Экспорт 73 строк из реального learned capture и CUDA-воспроизведение текущей модели `da571fe0` прошли (`combat-objective-harness-v1-20261025/native-cuda-export-v2` и `cuda-finalized`). Исправлено сравнение стартового оружия: используется фактический замороженный случайный inventory, а не предположение Machinegun по имени loadout. Стартовые idle-диапазоны проверяются для всех 11 stock-оружий.

Однако finalizer сообщает `ordinary_training_eligible=false`, `ppo_training_ready=false`: обычный PPO-тренер пока не умеет обучать `memory_route_movement` и `fine_weapon_aim` текущих экспериментальных весов. Численное CUDA-воспроизведение не является поддержкой оптимизации. Ограничение не снято. Нового NN-обучения, продвижения весов и доказанного превосходства над правилами здесь нет.

Следующий этап: добавить поддержку этих блоков в CUDA-тренер с корректным продолжением optimizer/checkpoint, проверить градиенты и ограниченный учебный шаг, затем короткое сравнение на заранее фиксированных боях. Полный масштабный прогон до прохождения этого допуска не запускается.

Обновление позднее 25.10: отдельный совместный CUDA scope реализован; 204 habitat-рецепта переведены на revision 2 с явной наградой для незавершённых control handoff. Полный пилот и отрицательный результат короткой оценки описаны в [проверке совместного PPO](combat_full_joint_ppo_20261025.md). Предыдущие показатели и ограничения выше относятся к состоянию до этого пилота; ordinary trainer по-прежнему не объявляется допущенным.
