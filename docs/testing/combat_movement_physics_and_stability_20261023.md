23 октября 2026. Продолжение после отрицательного опыта с frozen temporal selectors. Рабочие боевые веса прежние; превосходство над правилами не достигнуто.

## Явная геометрия вместо frozen embedding: оба fit отрицательны

До fitting записан `../combat_movement_geometry_selector_protocol_20261023.json`. Использованы прежние14TRAIN/4development контекста, та же utility и500CUDA шагов. Это **исследовательское повторное использование development**, а не новое независимое подтверждение.

Для каждого кандидата строятся прогнозы из средних движений до Gaussian noise; frozen conditional aim и frozen motor учитывают предлагаемое движение. Такие признаки — mean-action approximation, не интеграл по шуму будущих действий. На вход общей сети подаются явные относительные признаки **каждого из восьми наблюдаемых enemy slots**, включая тип, позицию, скорость, известность и направление взгляда, bbox и прогноз относительной геометрии. Отдельно используются26признаков движения и доступной геометрии стен. Seed/map ID, будущие native positions и результаты боя во входах отсутствуют. Признаки не ограничивают команды правилами.

Оба уступили своему постоянному распределению и по observed utility. Никаких дополнительных fit/checkpoint searches, новых quality игр или runtime внедрения этих endpoints не было. Source actor/critic/attention/aim/fire/weapon/std/predictor/checkpoint/Adam/RNG файлы не менялись. Причина предыдущего провала не сводится к доказанной нехватке размера сети; увеличение сети теперь не является следующим действием.

## Новый проверяемый вопрос: устойчивость дальнейшего исхода

Следующий протокол `../combat_movement_continuation_stability_protocol_20261023.json` зафиксирован до повторов. Взяты минимальные TRAIN сиды по каждой из четырёх карт, без выбора по результату альтернатив. Для каждого момента меняется только последующая случайность политики сF+1; исходный мир и prefix через вмешательствоF прежние. Дополнительные три потока заранее заданы. Это повторы будущей политики в фиксированных мирах, а не независимые environment seeds.

Реализован диагностический `combat_policy_continuation_rng_fork_v1`. Main PRNG сбрасывается один раз на точном кадреF+1; для последующих frame-hash aim choices используется объявленный seed. NN/std и temporal memory не меняются. `sample.sampling_seed` сохраняет исходный seed эпизода; новый receipt явно записывает effective fork seed, reset, Gaussian noises и fire uniform. Обычные PPO, corpus processing и quality evaluation отвергают эти модели. Логарифм вероятности действия сохраняет обычную нейронную плотность; fork меняет выборки, а не распределение выходов NN при фиксированном состоянии.

Чистые Go metadata/scalar/PRNG tests и сборки прошли без CPU NN. Native smoke4/4 иCUDA4/4 завершены. Причинная приёмка2/2: no-fork replay полностью воспроизвёл старый ordinary baseline; forked zero-shift полностью воспроизвёл fork-only reference; prefix/состояние/исходные и последующие общие draws совпали. До конца задачи правила не вмешивались.

В единственном smoke base3/seed1164065144 прежний нулевой контроль выигрывал с26полученного урона, а с новым потоком после того же состояния проиграл с80. Сдвиг влево при этом новом потоке тоже проиграл, но убил одного противника вместо нуля. Один такой пример доказывает зависимость конкретного продолжения от дальнейшей случайности; ещё не устанавливает частоту смены предпочтений или ожидаемую полезность любого манёвра.

Подготовлен общий пакет85native/CUDA:12единиц «4контекста ×3новых потока», все прежние допустимые манёвры, собственные fork-only references и четыре no-fork replay. Запущен существующим динамическим пулом16×2. Результаты полной устойчивости на момент записи этого раздела ещё не получены. Нового обучения нет; rejected selectors не участвуют.

## Завершение повторов: 20:50 МСК

Все85native/85CUDA завершены, source fingerprint неизменен. Строгая полная запись прошла11из12групп; однаcity1группа сохранена как excluded в исходных `proofs/` и `dataset/`, gate=false. Причина локализована: обе версии выиграли с одинаковыми kills на189/226/238кадрах и health1; все общие состояния/действия совпадают, но один capture закончился на242, другой на243. Разница — лишний кадр и отсутствие последнего next observation **после выполненной цели**, не расхождение NN действия до неё.

Первый отдельный goal-tail supplement тоже корректно отказал: экспорт последних шагов имел `available=false, reason=no_next_observation`. Эти записи не были объявлены нулевыми. Второй заранее записанный supplement потребовал независимого доказательства из raw server.log: точное native command window присутствует и завершено, никаких `sv_test_damage` в нём нет; все остальные известные post-goal эффекты нулевые, оба полных capture без смерти. Эти требования выполнены. Ни игры, ни utility labels, ни исходные отказы не переписаны, численные tolerances не менялись.

Отдельные `proofs-native-tail-v2/` прошли12/12групп. В11контролях полная запись совпала; для одной группы явно сохранено `zero_fork_full_exact=false`, а принят только точный наблюдённый боевой участок с подтверждённым пустым хвостом. Это не утверждение о совпадении неизвестного состояния после окончания записи. Пример контроля без изменения самого кадра манёвра: base3 выигрывает исходное продолжение и проигрывает/не завершает цель во всех трёх новых; city1 проигрывает исходное и первое новое, но выигрывает второе и третье. Выбор «лучшая альтернатива одного прогона» часто отражает последующий случайный ход боя. Это конкретная проблема текущего supervised teacher, но не доказательство единственной причины прежних PPO неудач.

Следующий ограниченный опыт зафиксирован в `../combat_post_variance_next_steps_20261023.md`: проверить только уменьшение непрерывного шума текущей policy с сохранением всей сети, прежде чем тратить большой бюджет на multi-continuation teacher. Два варианта — movement std×0,25 и all std×0,25; новый32native/24CUDA screen сsource/rules, затем только по gate независимое подтверждение. Это калибровка std, не очередное обучение отклонённых голов. После неё — новые усреднённые метки и, если нужно, action duration; рабочая цель превосходства над правилами остаётся открытой.

Смена знака не означает, что полезных действий в среднем нет. Напримерware2/backward имеет наблюдённую среднюю delta2,875при диапазоне от−0,25до+6,34. Четырёх продолжений недостаточно для объявления истинногоQ; задача следующего учителя — оценивать среднюю полезность и её разброс, а не требовать выигрыша каждого случайного продолжения.

Дополнительно реальный обычный `q2ppo-data` отверг fork-only модель **до создания output и до NN evaluation**: `inference-only, deterministic or diagnostic rollout cannot train PPO`. Квитанция `combat-continuation-ordinary-export-rejection-v2-20261023`. Первый тестовый wrapper ожидал более поздний текст ошибки и сохранил failed assertion отдельно; поведение exporter было правильным в обеих попытках. Дополнительных игр/обучения не было.
