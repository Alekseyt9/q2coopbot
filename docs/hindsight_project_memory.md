# Память проекта Hindsight

Настроена25.10.2026 по запросу пользователя: `openai-codex`, `gpt-6-luna`, reasoning `low`, авторизация через подписку ChatGPT. База и документы остаются локальными; тексты для извлечения фактов и сводок отправляются OpenAI. Gemma не используется. Эта память помогает разработке проекта и не является GRU/attention-памятью игрового бота.

## Размещение

- API: `http://127.0.0.1:9077`, банк `coding-agent::quake2`, MCP `hindsight_local`.
- Среда и служебные файлы: `F:/src/hindsight-local`.
- PostgreSQL: `F:/src/hindsight-local/data/postgres`, локальный порт54577.
- CPU embeddings: multilingual-e5-small ONNX; reranker RRF. Видеопамять для памяти не требуется.
- Python памяти: `F:/src/hindsight-local/.venv/Scripts/python.exe`.
- Python обучения бота остаётся отдельным: `F:/src/strat/.venv-gpu/Scripts/python.exe`.

## Источники и актуальность

Пакет необходимых источников описан в `F:/src/hindsight-local/project-knowledge-20261025/manifest.json`: путь, SHA256, операция загрузки, признак извлечения фрагментов. Он охватывает устройство проекта, планы System1, реестр эпизодов, пул инстансов, недавние отрицательные опыты и причинную проверку выбора оружия. Большой основной план импортируется фрагментами; полная хронология остаётся в репозитории. Целые старые чаты и тяжёлые JSONL прогонов не импортируются автоматически.

`retainSessions=false`, `codebaseSurvey=false`, `gitIngest=none`: автоматическая загрузка всего старого чата отключена после обнаружения задачи на1.25млнтокенов. В текущей конфигурации долговременные выводы нужно сохранять явно небольшими документами. Исходные файлы, численные отчёты и действующие инструкции пользователя важнее сводки памяти. Старые решения о CPU-обучении и ранние удачные screens не являются текущими правилами или доказательством превосходства.

Перед задачей выполняется поиск страниц знаний; конкретные результаты проверяются по исходным отчётам. Если факты устарели, загружается документ `Correction: ...`. После существенного изменения источников страницы обновляются последовательно. Нельзя считать `ok` при постановке документа в очередь доказательством завершения обработки.

## Запуск и авторизация

Подготовка конфигурации: `F:/src/hindsight-local/prepare_codex_api.py`. Запуск: `F:/src/hindsight-local/run_api.py --host 127.0.0.1 --port 9077 --no-access-log` через Python памяти. Приватные конфиги, токены и PostgreSQL URI не копировать в Git или отчёты.

Текущая схема использует отдельную копию только access token; интерактивный refresh token не разделяется и не изменяется. При каждом старте копия обновляется из действующего входа Codex. На момент настройки оставалось примерно152часа. Долго работающий процесс не получает бесконечную авторизацию: перед истечением нужен новый действующий access token и перезапуск сервиса. Для независимой постоянной работы предпочтителен отдельный OAuth-вход Hindsight, а не копирование refresh token интерактивного Codex.

## Проверка

- `F:/src/hindsight-local/finish_knowledge_pack.py` ждёт конкретные операции загрузки, затем обновляет страницы последовательно. Результат `complete.json` появляется только после успешных загрузок и непустых страниц.
- `F:/src/hindsight-local/audit_memory.py` сохраняет выдачу и проверяет наличие известных фактов и точных показателей пяти вариантов. Это smoke, не общая оценка качества памяти.
- Свежие сводки нужно прочитать и проверить на отрицания, численные значения, план/реализацию и ссылки на источники.
- Исправление локального адаптера SSE и модельные тесты: [отчёт](testing/hindsight_codex_models_20261025.md). Обновление пакета может перезаписать локальный патч.

Память не означает, что обученная боевая модель уже превзошла правила. Последний закрытый weapon-only pilot этого не показал; следующий причинный probe описан отдельно и требует реализации и живой проверки.
