# Пакетный сбор последствий манёвров

Исследовательский инструмент для полного обучаемого боя. Он собирает реальные альтернативы горизонтального движения из одинакового состояния; готовая игровая политика этим сбором не заменяется.

## Вход и выбор

`scripts/collect_combat_movement_pairs.py` принимает закрытый корпус из 32 обычных боёв с `frozen_world_v1` и зафиксированный `combat_movement_pair_collection_protocol_20261023.json`. Подготовку и CUDA-доказательства выполняет существующий `prepare_combat_movement_probe_cuda.py`, дополненный `--list-only` и `--context-id`.

На каждом сиде выбирается максимум один поздний наблюдаемый момент: бот жив, стоит на земле, стреляет автоматом, видит parasite в пределах 288 units. Предпочтение отдаётся движению и прицеливанию в другой класс. Будущие альтернативные исходы не участвуют в выборе.

Первые три позиции сида в каждом семействе доступны для TRAIN, четвёртая — только для внутреннего development. Квота семейства — до двух TRAIN и одного development. Обе части физически происходят из TRAIN-раздела реестра; development отделён по целым сидам и запрещён для fitting. Это не confirmation и не финальная оценка качества.

## Исполнение

Все подготовленные варианты поступают в **один** существующий динамический пул: до 16 слотов, ×2, следующий бой занимает освободившийся слот. Отдельные последовательные пулы на каждый контекст не создаются. Проверяется совпадение фактической generated fixture с исходной, включая позиции, здоровье, оружие и generation seed.

Готовится нулевой контроль и четыре осевых сдвига среднего движения ±1,25; сдвиг к нулевому среднему включается только в допустимых пределах ±2. Веса, std и порядок случайных выборок прежние. Прицел и fire пересчитываются по фактическому sampled movement. Нейросетевые доказательства выполняются CUDA; Go выполняет NN только в реальной игре.

Экспорт выполняется четырьмя процессами без CPU neural forward. CUDA-финализация — одним интерпретатором с независимым контекстом каждого боя. Сбор требует минимум 32 GiB свободного места; игровые ресурсы PAK/AAS не копируются этим координатором.

## Приёмка и метки

`audit_combat_movement_probe.py --context-index N` проверяет отдельный контекст общего закрытого пула. Требуются полное совпадение zero-control с обычным baseline, одинаковые префикс и состояние вмешательства, те же Gaussian noise/fire uniform и остальные категории. Правила не должны управлять незавершённым боем после вмешательства. Успех технического native/CUDA pipeline сам по себе не означает допуска меток.

`build_combat_movement_pair_dataset.py` сохраняет только принятые измеренные варианты и отдельные исключения. Непроверенные варианты не получают отрицательных меток. Return — наблюдённое конечное продолжение без critic bootstrap; это не ожидаемое Q действия. Gate и определение полезного варианта берутся из предварительного протокола; исходы не служат поводом менять квоты или пороги.

В конце существуют отдельные квитанции: `complete.json` для native/CUDA захватов, `proofs/<context>/report.json` для причинной приёмки и `dataset/report.json` для допуска к последующему исследовательскому обучению. Верхний `progress.json` описывает весь pipeline. Успех capture-квитанции при failed proof/dataset не означает готовности обучать модель.

## Запуск

Из корня репозитория, после проверки свободного диапазона портов:

```powershell
& F:\src\strat\.venv-gpu\Scripts\python.exe scripts/collect_combat_movement_pairs.py `
  --corpus workspace/artifacts/combat-movement-frozen-clock-baselines-v2-20261023 `
  --protocol docs/combat_movement_pair_collection_protocol_20261023.json `
  --out workspace/artifacts/combat-movement-pairs-v1-20261023 --port 46700
```

Выходной каталог должен быть новым. При ошибке нельзя повторно запускать native бои только из-за задержки наблюдения: сначала проверяются действующие процессы и квитанции этапов. Возобновление частичного захвата этим новым координатором пока не реализовано. Существующие успешные захваты нельзя молча перезаписывать или считать новыми независимыми сидами.
