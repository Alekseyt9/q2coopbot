# Уточнение идентичности в grid audit, 23.10.2026

Записано после закрытия25 native/CUDA случаев и первого строгого аудита. Исходный frozen protocol и результаты v1 не изменяются; новых игр или fitting нет.

v1 принял13 категорий, из них четыре попадания. В11 отклонённых случаях первое сырое расхождение на frame98 — ID parasite530 против528 в enemies/remembered_threats. В проверенных примерах остальные поля совпадают. У category8 отдельно отличается AgeMS head timing на frame146 (1ms против0ms); этот случай остаётся неприемлемым для заданного строгого сравнения.

Дополнительный v2 аудит разрешает только стабильное взаимно однозначное переименование id внутри enemies/remembered_threats на всём префиксе. Порядок объектов, observed_track, тип/модель, позиции, скорости и все остальные поля сохраняются и сравниваются. Encoded features, actor memory, исходные draws, команды префикса и timing в момент вмешательства по-прежнему должны совпасть. Отображение ID и факт несовпадения сырых наблюдений сохраняются в отчёте. Native попадание в выбранного врага связывается с фактическим ID своего запуска, не с каноническим номером.

Это явное различение имён игровых объектов и физического состояния. Оно не разрешает игнорировать любое другое расхождение или ослаблять timing для получения полного25/25. Если новые отличия сохраняются, соответствующая категория исключается. Это диагностическое уточнение после наблюдения данных, не предзарегистрированная новая оценка качества.

v2 сохранил13 принятых случаев: тот же raw ID хранится также в observation.history[].enemies и previous_target_intent.entity. v3 применяет одно и то же стабильное отображение к этим ссылкам. История/intent целиком не удаляются: все остальные значения, выбранный объект, порядок и физика по-прежнему обязаны совпасть. Старые v1/v2 отчёты сохраняются.
