# Продолжение после неподтверждённой передачи управления

23 октября 2026. Оригинальный geometry PPO B/G опыт остановлен аудитом второго G корпуса. Его критерии не меняются задним числом. Сохранены первый раунд обеих веток, второй раунд B, все 96 native/CUDA captures и исходный failure log. Новая оценка прежней незавершённой пары не требуется.

Подтверждённая проблема: jail1 seed1174065121 потерял наблюдаемый контакт с последним живым противником. На переходе frame380→381 закончился visibility grace и управление перешло правилам. Старое обнуление bootstrap при любой передаче управления неприменимо к завершению всего боя. Нельзя исключать такие проигрышные/незавершённые состояния ради прохождения квоты.

## Уже сделано

- Явный опциональный `RewardConfig.HandoffBootstrap=nonterminal_v1`, новый config SHA при включении. Старые коэффициенты/награды по умолчанию не изменены.
- `ZeroBootstrap`: смерть/terminal или доказанный goal handoff закрывают будущую ценность; прочий законченный native handoff сохраняет next-state potential и value. Сам GAE сегмент всё равно обрывается, поэтому последующие rule actions не приписываются политике.
- Supervisor `goal_handoff_verified` и интервал kill/observed frames — только offline label. `q2ppo-data` сначала проверяет исходный goal receipt, затем маркер. Старый exporter для нового goal-контракта не подходит; новые captures должны сохранять новый exporter.
- Legacy PPO export отвергает unfinished handoff до CUDA. Новый mode явно указан в метаданных.
- Native-credit и GAE audit различают completed goal и unfinished bootstrapped handoff. Dedicated geometry trainer требует совпадения явного протокола с mode в метаданных.
- Чистые scalar Go-тесты и сборки экспортёров прошли. На исходном проблемном бою новый replay сохранил states/actions точно; CUDA проверила 283 перехода. Вместо принудительного0 next_value=0,7678163. Диагностический корпус не допускается в PPO.
