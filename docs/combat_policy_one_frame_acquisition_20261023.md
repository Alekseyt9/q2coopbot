# Парные действия на фоне обычной политики

23 октября 2026. Следующий этап после отрицательного shared confirmation и отрицательного сравнения immediate/return teacher. Цель — новые независимые состояния и корректное продолжение обычной policy после одного вмешательства. Это сбор TRAIN примеров; превосходство над правилами ещё не достигнуто.

## Версия диагностического режима

Старый combat_joint_aim_one_frame_probe_v1 остаётся без изменения смысла: постоянная baseline голова, одна подмена. Новый combat_joint_aim_one_frame_policy_probe_v2 допускает обычную flat или shared голову. В указанном observation frame заменяются только25категориальных logits; вне кадра выполняется исходная сеть. Параметры, Gaussian source draw, target/mode/weapon/vertical/movement, порядок RNG и правило final-aim fire не меняются. Последующее состояние и решения могут изменяться из-за вмешательства; они не обязаны совпадать после него.

Это диагностическое распределение: обычный PPO и quality evaluator его отвергают. Новый probe не становится способом продолжения training checkpoint. Metadata validation не оценивает сеть наCPU. Все numerical/NN проверки — CUDA, Go NN только в живой игре.

Перед сбором: metadata unit test, Go build, CUDA проверки flat и shared на43существующих состояниях. Logits вне выбранного кадра должны совпасть побитно, все нейронные параметры должны сохраниться, probe должен отвергаться обычным scorer. Это численная приёмка, не новые учебные метки.

## Одно состояние на независимый сид

Выбирать не больше одного состояния на каждый seed, не ранее первого provider frame+10. Только matched/exclusive first-life windows без recovery commands, один реальный MG shot, выбранная eligible цель и фактическая category0. Желаемый исход baseline — miss/hit по чётности (индекс семейства в отсортированном списке + слотseed); это балансирует обаsplit. Если желаемого исхода нет, использовать другой. Предпочитать движение≥50units/s и |recoil pitch|≥1°, затем меньшийframe. Если ничего нет — фиксировать отсутствие, не возвращаться в начало боя ради квоты.

Категории:baseline0,две лучшие ненулевые frozen hint оценки и две другие поSHA256(seed:frame:category). У baseline0 в кадре использовать записанный обычный CUDA векторlogits, а не bias последнего слоя. До запуска обязательно проверить наCUDA исходные категории всей истории, точное равенство logits вне кадра и выбор нужной категории в кадре. Все веса variant отличаются только диагностической metadata; training checkpoints на каждый вариант не копировать.

## Живая приёмка до расширения

Первым взять минимальный по(seed,frame) выбранныйtrain контекст. Выполнить только его5вариантов и полнуюnative/CUDA проверку. Baseline должен воспроизвести исторические физику/features/actions/draws до вмешательства; дополнительно проверить весь baseline бой, а не один префикс. Фактические HP/выстрелы и исключения сохранять, entity IDs сравнивать допустимой стабильной bijection без изменения физики. После принятого smoke собрать остальные контексты одним пулом, исключив уже использованный; максимум ещё155native/155CUDA. Не повторять smoke скрыто в полном наборе. Если smoke не принят — исправить техническую причину, не запускать расширение.

Все контролируемые изменения внеframe должны быть запрещены. Новые датасеты должны хранить source policy SHA и split. Return labels из старой constant continuation и новой обычной policy не смешивать как один и тот же Q-target. Не использовать validation/confirmation для градиента. Дальнейший fitting protocol зафиксировать до обучения; недостаток независимых seed/geometry показать явно. Основные веса автоматически не менять.
